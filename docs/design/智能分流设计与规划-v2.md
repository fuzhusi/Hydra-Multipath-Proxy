## 一、一句话现状

规则代理已在**三端全量落地并统一**：桌面 TUN（IP 判定）、桌面本地代理（域名判定）、安卓 VPN（IP 判定 + protect 直连）——**一份规则文件、一个开关，驱动全部路径**。

## 二、现行架构（终态）

### 2.1 双模判定引擎（hydra-core/src/routing_rules.rs）

```
规则文件 rules.txt（UTF-8，三端同格式）
├─ 域名规则（本地代理路径消费）
│   ├─ DOMAIN,api.example.com,DIRECT        全等
│   ├─ DOMAIN-SUFFIX,example.com,DIRECT     后缀（含裸域，Clash 惯例）
│   └─ DOMAIN-KEYWORD,google,PROXY          包含
├─ IP 规则（TUN 路径消费）
│   ├─ IP-CIDR,1.2.3.0/24,DIRECT            v4/v6
│   ├─ GEOIP,CN,DIRECT                      内置表（v4 4115 段 + v6 2012 段，97KB 内嵌）
│   └─ DST-PORT,8080,DIRECT                 端口（最高优先例外层）
└─ 内置直连层（恒启用，优先于一切）
    ├─ 私网/回环/链路本地/CGNAT/ULA（显式清单）
    └─ 内置 CN 域名表（本地代理路径）/ CN IP 段表（TUN 路径）
```

- `decide(SocketAddr) -> Decision`：TUN 路径（每连接一次，二分 O(log n)，零分配）
- `decide_domain(host, port) -> Decision`：本地代理路径（域名规则 → 端口 → CN 域名表 → 默认）
- 已知取舍（文档化）：① 域名路径无法识别非回环私网名（nas.lan 类默认走节点）；② 自定义 CIDR ≤16 条线性（文件序首中）/ >16 条合并索引（start 小者优先、同 start 文件序）——两路径在左延伸重叠形态结论可能不同

### 2.2 三路径接线

| 路径 | 判定 | 直连形态 | DNS 策略 |
|---|---|---|---|
| **桌面 TUN** | `decide(SocketAddr)` | bind 物理 IP（Windows 强主机）+ protect 钩子透传 + 3s 超时回退 | 规则模式强制 DNS 直连 + 端口 53 UDP 强制 DIRECT |
| **桌面 SOCKS/HTTP** | `decide_domain` | `try_direct`（既有语义，失败回退节点） | 无需（浏览器报域名，无 DNS 依赖） |
| **安卓 VPN** | `decide(SocketAddr)` | **protect 形态**（无 bind，`VpnService.protect(fd)` 后通配 bind 直发） | VpnBuilder DNS 切 223.5.5.5/119.29.29.29 + 53 端口 protect 直发直连 |

**安全兜底（三端一致）**：直连失败/超时/protect 失败 → **一律回退走节点**，永不因分流断网；规则文件损坏 → 降级内置 CN 表（日志+UI 如实告知）；非 Windows 非 Android（无保护钩子的裸 Linux）→ 直连显式禁用走节点（待 SO_BINDTODEVICE）。

### 2.3 UDP 直发池（双形态）

- bind 形态（桌面）：bind 物理 IP 直发 + NAT 表（客户端源地址键控）+ dst_allow 来源白名单（LRU 上限 8）+ 泵任务回收即释放 fd
- protect 形态（安卓）：通配 bind + `protect_outbound_fd`，其余同上
- 150s 空闲回收 / 512 会话上限
