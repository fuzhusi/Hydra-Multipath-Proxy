# 安卓端日志与健康观测方案 v1

> 日期：2026-10-18 ｜ 状态：方案待确认（用户提出：连接后周期测速入日志 + 异常自动记录）
> 现状基线：0.2.8-preview（日志页仅有 Kotlin 层启动步骤，Rust 数据面事件不可见）

---

## 一、现状问题（已核实）

| # | 问题 | 根因 |
|---|---|---|
| L1 | 日志只有「①读取配置 ②已加载 ③建立 TUN ④启动栈 ✓已接管」 | `EngineState.addLog` 只被 Kotlin 侧调用；**Rust 内核 tracing 事件不进应用日志页**（桌面端批次 A 已做桥接层，安卓没有对应实现） |
| L2 | 运行期（连接后）零日志 | 无周期性状态输出；内核的每连接事件、丢弃事件、异常都不落 UI |
| L3 | 无网/网络异常无感知 | 无健康探测、无 ConnectivityManager 监听；用户只能看到「已连接」假象 |
| L4 | 日志无级别区分/过滤/导出 | 安卓日志页只有纯文本列表（桌面已有级别徽章+文本/方向筛选+导出） |

## 二、方案（三层，按优先级）

### A. 内核事件桥接（基础，必做）
- Rust 侧新增 **日志环形缓冲**（同桌面 log_bridge 思路）：`hydra-android` 注册 tracing Layer，把事件写入 `Mutex<VecDeque<(level, msg, ts)>>`（容量 500，满丢最旧，字段化+掩码）
- uniffi 暴露 `vpn_logs_since(seq) -> Vec<VpnLogEntry>`（增量拉取，seq 游标）——复用 `vpn_stats()` 同款轮询模式
- Kotlin：现有统计轮询循环内一并拉日志（1s 间隔），去重后 append 到 `EngineState.logs`（上限 500）
- 效果：连接/断开、直连/中继决策、DNS、丢包、警告**全部可见**

### B. 周期健康探测（用户建议核心）
- 连接成功后启动探测循环：**默认 300s（5 分钟）**——与 Clash url-test 默认 interval 一致（sing-box urltest 默认 3m）；可配置 1m/3m/5m/10m/关。**另在连接建立与网络切换瞬间各触发一次即时探测**（5 分钟间隔对排障太稀疏）
- 探测内容（轻量、单次）：① DNS 解析 `223.5.5.5` 或系统 DNS ② TCP 连接节点（复用既有节点测试逻辑）③ 可选 HTTP HEAD 到 `http://connect.rom.miui.com/generate_204` 类端点（200/204 即通，字节数极小）
- 日志输出：`✓ 健康检查通过（DNS 12ms · 节点 89ms · HTTP 204 320ms）` 或 `✗ 健康检查失败（DNS 超时 · 节点可达 · HTTP 失败）`
- 失败策略：连续 2 次失败 → **升级为 warn 日志 + 通知栏提示「网络异常」**；连续 5 次 → 记录「疑似断网，建议切换节点/网络」；探测失败不影响数据面

### C. 网络事件与异常日志
- 注册 `ConnectivityManager.NetworkCallback`：网络切换（WiFi/4G）、丢失、恢复 → 写日志（`网络已切换到 WiFi` / `网络已断开` / `网络已恢复`）
- 数据面异常（已有 Rust 事件经 A 桥接）：`数据面退出`、`连续 5 次数据面退出`、`TUN 丢弃 UDP 包`、`通道重建` → 自动进日志
- 用户「没网」时的排障路径：日志里直接能看到 DNS/节点/HTTP 三段探测结果 + 网络事件时间线

### D. 日志页 UI 增强（对齐桌面）
- 级别徽章（Info/Warn/Error 着色）+ 级别过滤 + 关键字搜索 + 一键导出（复制/分享文件）+ 清空
- 自动滚动（新日志在底）+ 暂停滚动开关（排障时看历史）
- 沿用 HydraTheme 令牌，不新造组件

## 三、性能与边界

| 项 | 约束 |
|---|---|
| 探测开销 | 30s 一次、单 TCP + 单 HTTP HEAD（≤1KB）；失败退避到 60s；VPN 未连接不探测 |
| 日志内存 | 环形 500 条 × ≤200B ≈ 100KB 上限 |
| 日志持久化 | 可选开关：写 `files/logs/hydra-vpn.log`（每日滚动、7 天保留；默认关） |
| 安全 | 目标掩码沿用 `mask_target`；日志不上传；导出前提示包含本机信息 |
| 隐私 | 服务名/IP 脱敏级别与桌面一致（目标打码，域名保留首尾字符） |

## 五、已确认决策与剩余项

已确认：
1. **探测间隔 = 300s**（对齐 Clash url-test 默认；可配）+ 连接/网络切换时即时探测
2. **日志纯内存不落盘**：点击连接即开始记录；划掉后台/服务停止即清空；存续期间可导出

已定稿（工程判断）：
3. **探测组合（比单一 204 端点更准）**：① 节点 TCP 直连（物理路径，判节点与载体网络）② **隧道内 DNS 查询**——Kotlin 用未 protect 的 DatagramSocket 向 223.5.5.5:53 发一次 DNS 查询（会进入 TUN → 中继 → 返回，**真实测隧道全链路**）；③ 可选 HTTP 204（`http://connect.rom.miui.com/generate_204`，国内可达；不用 gstatic——墙内必失败造成误报）。三项分别计时入日志，单项失败不误判整体
4. **失败处理：只告警不自动切节点**（v1）——连续 2 次失败 warn + 通知栏；连续 5 次提示「建议手动切换节点/网络」。自动切换留给调度层（避免与最低延迟调度策略冲突），并在连续 5 次失败时记录「如持续失败请检查规则文件/节点订阅」排障引导
