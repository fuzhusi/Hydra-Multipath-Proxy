# 移动端应用交互设计（M1：本地代理应用）

> 上位文档：[移动端Android方案-v2](移动端Android方案-v2.md)（里程碑与架构）。
> 本文是**应用层**设计：页面、状态机、数据流、导入流程、错误矩阵、生命周期与
> UI 规范——M0 骨架与 M1 实现先于本文存在（过程倒置），本文按"如实记录现状 +
> 自评审找差距 + 按评审补齐"的方式补全流程，差距与决策见 §10 评审记录。
> 版本：v1.0（2026-10-08）。适用 versionCode ≥ 3。

---

## 1. 背景与目标

M1 形态 = **进程内 SOCKS5/HTTP 引擎 + 前台服务保活**。用户旅程：

```text
拿到配置（桌面端分享二维码/链接/订阅文本，或手动输入）
  → 导入（扫码 / 粘贴 / 深链 / 手动）
  → 启动引擎（前台服务 + 通知常驻）
  → 浏览器手动配置代理指向监听地址
  → 出网验证（连通性自检 ✓ + 页面可开）
```

目标（M1 验收口径）：
1. 从"拿到二维码"到"浏览器能出网"≤ 5 步操作；
2. 任何失败都有**可读的中文原因**和**可执行的下一步**（不留死状态）；
3. 密钥/证书加密存储，不进云备份；
4. 引擎生命周期对用户可见可控（通知常驻 + 事件时间线）。

M2 补充（本批交付）：VpnService 全局 VPN（含 consent 流程、onRevoke、通知
停止动作）、DNS 经隧道（系统 DNS 随全局路由进节点解析，加密无泄漏）、TCP
任意端口动态监听（SYN 驱动挂 listener，上限 256）——详见 HydraVpnService。
非目标（后续）：开机自启、节点手动选择/测速调度（M1 全部节点自动加权调度）、
配置导出。

## 2. 信息架构（三页导航）

| 页面 | 职责 | 关键元素 |
|---|---|---|
| 连接（Home） | 状态一目了然 + 启停 + 排障 | 状态主卡（ON/OFF 圆标、失败原因直达）、启停大按钮、监听地址（复制）、流量格、节点摘要入口、事件时间线 |
| 节点（Nodes） | 配置的节点管理 | 节点卡片（地址/删除/连通性测试）、空态引导、导入入口（FAB：扫码/粘贴/手动三路） |
| 设置（Settings） | 全局凭据与高级参数 | 凭据区（密钥显隐/实时校验、pin↔CA、证书导入及状态）、高级区（SNI、监听端口）、保存 |

导航：底部 NavigationBar；导入二维码/证书经系统 Activity（不占导航栈）。

## 3. 引擎状态机（单一数据源）

状态载体：`EngineState`（进程级单例，Service 写 / UI 订阅）。派生显示：

```text
           ┌────────────────────────────────────────────┐
           │  running=false, transition=null  →  已停止  │◄──────────┐
           └──────────────┬─────────────────────────────┘           │
                  点启动 ▼                                         ■停止/超时/失败
           ┌────────────────────────────────────────────┐           │
           │  running=false, transition="启动中/失败…"    │──失败────→┘（transition=
           │  （Starting：通知栏同步显示同一文案）          │            "启动失败：原因"）
           └──────────────┬─────────────────────────────┘
                建连成功 ▼
           ┌────────────────────────────────────────────┐
           │  running=true, boundAddr=…        →  运行中 │──■停止/服务回收──→ 已停止
           └────────────────────────────────────────────┘
```

不变量：
- **状态只由 EngineService 写**（UI 只读 + 发启停意图）——单一写者，无竞态；
- `transition` 非空 = 启停进行中或失败原因，主卡与通知栏显示同一文案；
- **失败/超时后必然回到可重试态**（`transition` 保留失败原因，按钮解锁）；
- 20s 看门狗兜底整个启动序列（阻塞 JNI 不可被协程取消，独立线程 + 启动代数
  计数防误伤重试）；
- `onDestroy`（系统回收）必须复位状态并写事件，防 UI 残留"运行中"。

## 4. 数据流与存储

- `SecureStore`：EncryptedSharedPreferences（Keystore 主密钥 AES256-GCM），
  `allowBackup=false`；Keystore 损坏（厂商 ROM）→ 降级普通存储 + 日志留痕
  （可用性优先，沙箱仍兜底，不防 root）。
- 字段：`nodes`（多行 addr:port）、`auth_key_hex`、`sni`、`trust_mode`、
  `cert_der_b64`、`listen_port`。全部显式保存（设置页"保存"；启动前自动保存）。
- `EngineState.logs`：进程级事件时间线（时间戳 + 文案，新条目在前，封顶 100），
  引擎/导入/服务回收全部留痕——真机排障的第一现场。

## 5. 导入流程（核心用户旅程）

输入四路，解析收敛到同一个 Rust FFI（`parse_share_text`）：

```text
① 扫码（桌面端分享二维码）──┐
② 粘贴链接/订阅文本 ────────┼→ parse_share_text → ParsedShare{nodes, 密钥, 证书, skipped}
③ hydra:// 深链（聊天工具）─┤      │
④ 手动输入 IP:端口 ─────────┘      ▼
                        合并落库：节点去重追加（手动节点不丢）；
                        密钥/证书仅当链接携带时覆盖（空 = 保留已存值）；
                        结果 toast + 事件留痕（含 skipped 条数说明）
```

不变量：
- 解析/合并只认 IP 字面量节点；域名节点计入 `skipped` 并向用户明示（M2 支持）；
- `cc=`（证书）与 `k=`（密钥）随链接自动提取——**分享链接导入后无需手动选证书**；
- 失败必须给出"为什么 + 支持哪些格式"，不得静默丢弃。

## 6. 连通性自检（引擎可用 ≠ 节点可达）

引擎"运行中"只代表本地监听就绪；**节点可达性是独立事实**，必须显式验证：

- **自动**：引擎就绪后自动对首个节点发起完整握手探测（TCP+TLS+Noise-PSK，
  与数据面同路径），结果写事件时间线（`节点连通 ✓ 123ms` / `⚠ 节点连通失败: …`）
  ——直接回答用户"为什么没有流量"的高频疑问；
- **手动**：节点页每卡片"测试"按钮，结果就地展示（延迟/失败原因）；
- 探测超时 8s；探测不改变引擎状态，只补充事实。

## 7. 生命周期与后台

- 前台服务（`dataSync` 类型）持有引擎：Android 11+ Cached App Freezer 会冻结
  后台进程，无 FGS 则切后台即死；
- 通知：常驻低优先级，实时显示监听地址/流量/连接数，**携带"停止"动作**；
- 启动时序：`startForegroundService` → onStartCommand 内立即 `startForeground`
  （满足 5s FGS 时限）→ 异步启动引擎；
- 进程回收：`onDestroy` 停引擎 + 复位状态（`START_NOT_STICKY` 不自动重启——
  静默重启的代理违背可预期性，M2 VpnService 形态再评估）。

## 8. 错误处理矩阵（失败 → 文案 → 用户动作）

| 失败点 | 用户可见 | 建议动作 |
|---|---|---|
| 导入：无法识别 | "未能识别任何可用节点（跳过 N 条）。支持 hydra://…" | 检查链接来源；改用手动输入 |
| 导入：域名节点 | "跳过 N 条（域名节点/坏行）" | 先在桌面端解析为 IP |
| 启动：密钥/证书缺失 | 启动失败 + 具体缺项（② 步日志可见） | 去节点页导入 / 设置页补全 |
| 启动：端口被占 | "5s 内未完成监听绑定" | 设置页换监听端口重试 |
| 启动：节点不可达 | 引擎就绪 ✓ + "⚠ 节点连通失败: …"（事件） | 查节点/网络；换节点 |
| 启动：病理性挂起 | "启动超时（20s）：请重试"（看门狗） | 重试；反复出现反馈事件 |
| 运行：节点中途失联 | 流量停止增长 + 连通性测试可复核 | 测试按钮复核；换节点 |

文案纪律：中文、说原因、给下一步；错误不静默、成功必有正反馈（✓）。

## 9. UI 规范

- Material 3；Android 12+ 动态取色（壁纸色），低版本回退默认 scheme；
- 状态色语义：运行=主题绿系（tertiaryContainer 系），停止=surfaceVariant，
  失败=errorContainer——**全部取自主题，不硬编码**（深浅色自适应）；
- 地址/流量等数值用 Monospace；层级：主卡 > 普通卡 > 辅助文字；
- 空态必须给"下一步去哪"的引导文案；
- 事件时间线：Monospace 11sp，连接页展示最近 8 条，"全部"对话框可看 100 条
  并一键复制。

## 10. 评审记录（对照现状的差距与决策）

对 M1/M1.5 现状逐节比对，发现差距与处置：

| # | 差距 | 处置 |
|---|---|---|
| R1 | **无连通性自检**——"引擎运行但没流量"无法自证（真机反馈的高频困惑） | 本批实现：自动探测（就绪后）+ 节点页手动测试（Rust FFI `test_node_connection`） |
| R2 | **无 hydra:// 深链**——聊天工具收到链接只能复制粘贴 | 本批实现：scheme 注册 + 导入收敛复用 |
| R3 | 导入对话框不读剪贴板（粘贴多一步） | 本批实现：打开时检测 `hydra://`/长 base64 自动预填 |
| R4 | 通知无"停止"动作（必须回应用内停止） | 本批实现：通知 addAction |
| R5 | 状态主卡/流量格硬编码深色（浅色主题突兀） | 本批实现：改主题容器色 |
| R6 | 事件只能看最近 8 条，不可复制 | 本批实现："全部"对话框 + 一键复制 |
| R7 | 启动失败后按钮曾无效、启动序列曾无分步留痕、无超时兜底 | 已在上一批修复（状态机不变量补齐），本文档化为规范 |
| R8 | 导入直接落库无预览确认 | 决策：保持现状（结果 toast + 事件 + 节点可删可重导，损失可控）；预览确认列为后续优化 |
| R9 | 端口冲突仅报错不引导 | 决策：错误矩阵已给动作（换端口重试）；一键换端口列为后续优化 |
| R10 | 扫码相机权限请求时机 | 已修：进应用即随通知权限一并请求 |
