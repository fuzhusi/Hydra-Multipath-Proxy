## 一、已修复项

### P0-1 UDP 回包校验和覆盖零载荷（最严重，影响既有功能）
- **位置**：`hydra-client/src/tun.rs` `build_udp_reply_v4/v6`
- **机理**：`vec![0u8; total]` → 填 UDP 头 → **算校验和** → 最后才 `copy_from_slice(payload)`。
  校验和覆盖的是全零载荷 → 所有非空回包校验和错误 → 本机 IP 栈静默丢弃
  （TUN 无 checksum offload，收包路径强校验）
- **后果**：应用侧「UDP 发得出去、永远收不到回包」——**UDP 直连分流与既有 UDP 中继回包全链路失效**，
  而日志/UI 显示一切正常。逃逸原因：既有 E2E 只逐字节比对载荷，从不验证校验和
- **修复**：载荷写入提前到校验和计算之前；v6 校验和为 0 时改写 `0xFFFF`（RFC 2460）
- **回归测试**（新增 2 条，能抓住该缺陷）：
  `udp_reply_checksum_covers_payload_v4/v6`——对回包做 RFC1071 反码和校验 == 0

### P1-1 规则文件存在但无 GEOIP 行时内置 CN 表被整体关闭
- **位置**：`hydra-core/src/routing_rules.rs:234`
- **后果**：用户写一条 `DST-PORT`/`IP-CIDR` 规则即静默丢掉全部 CN 直连（分流形同虚设）
- **修复**：`geoip_enabled` 默认 `true`（自定义规则是**叠加**在内置表之上）

### P1-2 NAT 会话回收不释放 socket（fd/任务/内存无界泄漏 + 幽灵 NAT）
- **位置**：`hydra-client/src/tun.rs` `UdpDirectNat::sweep_idle/ensure_session`
- **机理**：仅 `retain` 删表项，回包泵自持 `Arc<UdpSocket>`；未 `connect` 的 UDP socket
  无人发送时 `recv_from` 永远 Pending → 循环无退出路径 → fd/任务/64KB 缓冲永久驻留，
  且被"回收"的 socket 继续向 TUN 注入回包（投给已关闭/复用的端口）
- **修复**：`DirectUdpSession` 持有 `JoinHandle`，回收时收集过期 key → `remove` → `pump.abort()`
  （`JoinHandle` 非 Clone，故不能在被借用的会话上 abort）；新增会话表上限 `MAX_SESSIONS=512`
  （超限回收最旧会话）

### P1-3 该族无物理源 IP 时 TCP 直连裸连 → 自激回环风暴
- **位置**：`hydra-core/src/proxy.rs` `tun_rule_opener`
- **机理**：接管路由 `0.0.0.0/1 + 128.0.0.0/1`（metric 1）只豁免节点/DNS/私网；
  无 bind 裸 connect 按目的地址路由命中 /1 → 包回自身 TUN → `any_ip` 接受 → 再判 DIRECT → 再裸连，
  直至 `max_flows`（每 socket ~128KB 缓冲）
- **修复**：该族 bind 为 None 且无 protect 钩子时，**公网目标**直接走节点；
  **回环/私网/链路本地例外**（本就有豁免路由，且是 R5「私网 → 直连」的设计语义）

### P2-1 直连超时 10s → 3s
- 直连失败场景（黑洞丢 SYN）此前白等 10s 才回退节点；降为 3s（内层 `OPEN_TIMEOUT` 15s 仍有充足余量）

### P2-2 自定义 CIDR 二分阈值 50 → 16
- 20-49 条 CIDR 场景此前退化为线性扫描，与 R10 性能注记不符

### P3-1 GeoIP dat 段数溢出可 panic
- `n4 * 8` / `n6 * 32` 改 `checked_mul/checked_add`，损坏 dat 返回 Err 而非 debug panic / release 越界读
