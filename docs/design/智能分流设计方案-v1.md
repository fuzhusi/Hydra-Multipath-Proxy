## 〇、v1.1 修订记录（评审 R1-R10 合入）

- **R1（P0）UDP 分流**：规则判定接入 `try_forward_udp`（DNS 与数据 UDP 的公共分发点，tun.rs:1741）——UDP DIRECT 走「bind 物理 IP 的本机 UDP socket 直发池」（回包注入 TUN），UDP PROXY 走既有中继。**缺失后果**：QUIC/HTTP3（UDP 443）全走节点，TCP 分流形同虚设
- **R2（P0）DNS 策略联动**：规则模式默认 **DNS 直连解析**（`HYDRA_TUN_DNS_DIRECT=1` 联动，tun.rs:80-84 既有开关）——否则国内 CDN 站经境外节点解析返回海外边缘 IP（不在 CN 表内），GeoIP 对 CDN 主体流量静默失效；GUI 规则分流开启时提示该权衡
- **R3（P1）protect 钩子契约**：direct opener 必须统一走 `connect_tcp_protected`（socket_protect.rs:61，桌面零开销直通 / Android protect(fd) 防回环）再叠加 bind；bind/protect 双形态抽象（桌面=bind IP，Android=protect 无 bind）
- **R4（P1）源 IP 探测落点**：新增「本机物理网卡源 IP 探测」（Windows：`GetBestRoute` 返回源地址；通用：UDP connect + getsockname 技巧），失败 → 全部走节点（规则模式静默退化为全局代理，UI 必须可见）
- **R5（P1）私网兜底**：规则引擎内置最高优先级「私网/回环/链路本地 → DIRECT」（direct opener bind 物理 IP 后可访问 NAS/路由器，优于丢弃）
- **R6（P1）v6 GeoIP**：构建脚本同步产出 **v6 CN 段**（u128 数组）；直连 v6 源绑定失败（临时地址轮换/无全局 v6）→ 回退走节点
- **R7（P2）**：ICMP 现状静默丢弃不因分流改变——「CN 直连后 ping 不通仍属设计内」写入文档；真机验证项改「TCP 可用性 + IP 属地」
- **R8（P2）规则文件容错**：UTF-8 BOM/CRLF/行尾空白/`#` 内联注释容忍；GBK 非法 UTF-8 行告警跳过（不静默整表失效）
- **R9（P2）GUI 文案**：规则模式文案挂 **TUN 运行状态位**（「规则分流 · CN 直连 · 其余经节点」），不覆盖 boundAddr（本地监听地址语义保留）
- **R10（P2）**：端口规则示例改 `DST-PORT,x,DIRECT` 例外形态；性能注记：判定输入用 **SocketAddr**（tun.rs:2237-2257 已有原始形态，零解析零分配）、接线点 = **run_stack 入口包装 opener**（spawn_up_task/Flow 零改动）、自定义 CIDR 规则多时同样构建排序段二分
- **回退语义扩展**：直连 connect 失败/**独立短超时**（DIRECT_CONNECT_TIMEOUT，复用 proxy.rs:1332 既有常量，不复用 OPEN_TIMEOUT 15s）→ 回退节点（SOCKS 路径 try_direct proxy.rs:1324-1366 同语义先例）
- **4 项待验证**（真机）：① `/1` 接管下 bind 物理IP 出网；② 直连失败回退时延；③ top100 国内域名两种 DNS 配置的 CN 表外比例；④ DHCP 换 IP 的 bind 失效表现

## 一、目标与范围

TUN 模式新增**规则模式**：按规则决定每条连接「直连 / 走节点」，用户不再手动开关代理。

**v1 范围**：IP-CIDR 规则（含内置 GeoIP-CN 表）+ 端口规则；直连实现走「源地址绑定」。
**v1 不做**（记入 v1.1 候选）：域名/SNI 规则（需 TLS ClientHello 嗅探）、进程名规则、规则订阅远端更新、UI 规则编辑器（v1 用规则文件）。

## 二、核心难点与决策：直连如何绕过 TUN

TUN 模式下系统路由把全部流量送进 tun0——「直连」的连接若不特殊处理会被自己再抓回（回环）。两案：

| 方案 | 原理 | 判定 |
|---|---|---|
| A. 源地址绑定 | 直连 socket `bind(物理网卡 IP)` 后 connect——Windows 强主机模型下，绑定了源地址的 socket 按该接口路由出网，**不进 TUN** | ✅ **采用**：无路由表改动、粒度到每条连接、失败自动回退走节点 |
| B. 动态路由法 | 为直连目的地加 /32 路由指向物理网关 | ✗ 域名规则需解析后逐条加路由，竞态多、污染路由表 |

**实现**：`direct_opener(target)`——`TcpSocket::new → bind(物理网卡源 IP) → connect(target)`，成功后包成与代理通道同构的 `ProxyDuplex`（中继泵零改动，只换通道来源）。
物理网卡源 IP：TunConfig 新增 `direct_bind_ip: Option<IpAddr>`，由上层（RouteGuard/网关探测基建）在启动 TUN 时填入。

**回退语义**：绑定失败（取不到物理 IP/接口变化）→ 该连接回退走节点（永不因分流把用户断网）。

## 三、规则模型

### 3.1 规则类型（v1）

| 类型 | 语法（规则文件） | 匹配对象 |
|---|---|---|
| IP-CIDR | `IP-CIDR,1.2.3.0/24,DIRECT` | 目的 IPv4/IPv6（含 v6 段） |
| GeoIP | `GEOIP,CN,DIRECT` | 内置 CN 地址段表（聚合后嵌入式资源，约 50-100KB） |
| 端口 | `DST-PORT,443,PROXY` | 目的端口（次要，够用） |

### 3.2 匹配顺序（首个命中生效，评审 P2-3 文档对齐口径）

```
入站连接（IP:Port）
  1. 内置私网/回环/链路本地/CGNAT/ULA → DIRECT（最高优先）
  2. 端口规则（DST-PORT）——**最高优先例外层**（恒先于 CIDR）
  3. 自定义 CIDR 规则（IP-CIDR）：≤16 条按文件序首中；>16 条构建合并索引后
     按「start 小者优先，同 start 文件序优先」——两种路径在左延伸重叠形态下
     结论可能不同（已知取舍，避免每连接双路径对齐成本）
  4. GeoIP-CN 表（二分查找，预排序段数组）→ DIRECT
  5. 默认策略 → PROXY（走节点）
```

> v1.1 备注：端口规则不参与文件内「自上而下」排序——实现上恒定置于自定义
> CIDR 之前（端口例外层语义）；UDP DNS（端口 53）在 `dns_direct` 生效时
> 亦无条件直连（先于 GeoIP/默认策略）。

- v1 匹配键 = 目的 IP（TUN 栈天然提供）。域名规则 v1.1（需 SNI 嗅探）另行设计
- **DNS 决策（v1.1 候选，v1 维持现状）**：DNS 继续经节点解析（dns_via_proxy=true 不变）——缺陷：国内域名拿到对节点近的 CDN IP，可能被 GeoIP 判为国外走节点（体验折损，如实写入文档）；v1.1 引入「DNS 直连解析 + 透明改写」方案

### 3.3 GeoIP-CN 数据源

- 来源：公开的 CN BGP 聚合段（APNIC delegated 列表派生），构建脚本聚合相邻段
- 形态：构建期生成 `geoip_cn.dat`（排序 u32 段数组 + 二分查找），`include_bytes!` 嵌入——离线可用、无运行时下载
- 更新：构建脚本重新生成（README 注明数据时效）

### 3.4 性能

- GeoIP 查询：排序段二分 O(log n)，每连接一次（建连时判定并缓存到流上下文），热路径零新增分配
- 规则文件加载：启动解析一次，变更重启生效（v1 不做热重载）

## 四、配置与 UI

### 4.1 运行模式扩展（TunConfig/GuiConfig）

- `tun_mode: enum { Global, Rule }`（默认 Global——行为兼容）；`rule_file: Option<PathBuf>`（默认加载内置 GeoIP + 用户自定义 `rules.txt`）
- **规则文件**：`%APPDATA%\hydra\rules.txt`，UTF-8，`#` 注释；设置页提供「打开规则文件」按钮 + 重启生效提示（v1 不做热重载）

### 4.2 UI

- 设置页 TUN 区新增「分流模式」：全局接管（默认）/ 规则分流（单选）
- 规则模式选中时显示：当前规则文件路径 + 「打开规则文件」+ 生效规则计数 + 重启提示
- 首页状态摘要：规则模式下 boundAddr 显示「规则分流（CN 直连 · 其余经节点）」

## 七、风险

| 风险 | 缓解 |
|---|---|
| Windows 源地址绑定在部分网卡/VPN 共存场景不生效 | 失败自动回退走节点（永不断网）；真机验证项 |
| GeoIP 数据误判（CN 段遗漏） | 用户自定义规则兜底 + 数据构建脚本可持续更新 |
| DNS 经节点导致 GeoIP 判定偏移（CDN 出口在节点侧） | v1 文档如实声明；v1.1 DNS 直连解析方案 |
| R8/CI 对 include_bytes 资源 | 构建脚本 CI 生成，路径稳定 |
