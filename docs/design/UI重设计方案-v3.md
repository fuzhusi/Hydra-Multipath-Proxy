# Hydra 客户端 GUI 重设计方案 v3（对标 Clash Verge Rev / V2rayN）

> 面向实施的设计文档 · 目标代码库：`hydra-client-gui`（egui/eframe，`src/main.rs` 约 3236 行）· 暗色优先

## TL;DR

- **结论先行**：保留 egui 走"强化路线"（推荐），即用 egui 原生能力复刻 Clash Verge Rev 的**左侧窄侧栏 + 顶栏 + 内容区卡片**布局，配合自定义 `Visuals` 暗色主题、egui_plot 速率图、自绘延迟色点、`egui_extras::Table` 排序连接表。**不迁移框架**。
- 理由：现有 GUI 的全部难点（托盘、二维码、订阅后台线程、健康检查通道、配置持久化）都已跑通且与 egui 无耦合；换框架（Tauri+Web）能拿到更好看的皮，但要重写全部状态管理并引入 Node 前端工具链，投入产出比低。egui 完全能做侧栏+卡片+表格+色点，只是默认皮肤丑——**丑在默认 Visuals，不在能力**。
- 信息架构从六区收敛为 **7 页对齐 Clash Verge**：`首页(仪表盘) / 代理(节点+组) / 连接 / 分享 / 订阅 / 日志 / 设置`；系统代理开关和运行开关固定在**顶栏右侧**（Verge 模式），托盘菜单与之同步。
- 实施分三阶段：**P0** 拆分 main.rs 为模块 + 侧栏导航骨架（~3 人日）；**P1** 仪表盘 + 代理页重做（~4 人日）；**P2** 连接页 / 主题打磨 / 微动画（~3 人日）。合计约 10 人日。
- 功能零丢失：节点管理/手动测速/分享二维码/导入/订阅/国内分流/托盘/系统代理全部保留并重新安置。

## 竞品分析

### 1. Clash Verge Rev（Tauri + React，对标首选）

基于公开资料（官网文档、GitHub repo、DeepWiki 架构分析、社区教程图文）：

- **整体布局**：左侧固定窄侧栏（约 56–72px，图标+小字），自上而下：`代理 / 首页(概览) / 连接 / 规则 / 日志 / 订阅(配置) / 设置`；底部是主题切换与版本信息。内容区为宽卡片流。
- **首页/概览页**：大卡片网格——当前流量上下行速率（实时曲线图）、连接总数、内存占用、当前节点与代理模式（规则/全局/直连）展示，卡片右上角有刷新图标。
- **代理页**：顶部按**代理组**分区（Selector / URLTest 等每组一个横向区块），组内节点为可换行的**卡片/胶囊（chip）**；每个节点右侧显示**延迟色点+毫秒数**（绿 <200 / 黄 <500 / 红 ≥500 / 灰 未测），组头部有**闪电测速按钮**一键测全组，支持延迟排序；顶部全局有代理模式切换三态按钮。
- **连接页**：实时连接表（默认隐藏暂停按钮），列：主机、下载/上传、速率、链路（节点链）、规则、时间；顶部搜索框按主机/进程过滤，可单条关闭连接。
- **订阅页（Profiles）**：订阅卡片网格（卡片含名称、更新时间、右键菜单：更新/编辑/删除/设为激活），顶部有"新建/导入"按钮；每张订阅卡可拖拽排序（网格化）。
- **设置页**：分区折叠/分块——系统设置（开机自启、静默启动、托盘、系统代理开关、TUN 模式）、Clash 核心设置、外观（主题/字体/圆角）、UI 保留（外部控制、密钥）等。
- **日志页**：级别过滤器（info/warn/error/debug）+ 实时滚动列表。
- **托盘**：显示/隐藏窗口、代理开关、TUN、模式切换、自动延迟测试、退出。
- **交互语言**：一切皆"卡片 + 圆角 + 低对比分隔线 + 单色图标"，暗色为主（亮暗主题跟随系统可选），强调色一个（主色），延迟绿/黄/红是唯一功能性用色。

### 2. V2rayN 6.x（WinForms/WPF 传统列表风格）

- 主界面为**双栏布局**：左侧窄条（服务器/订阅/路由/设置等主菜单入口 + 分组树），右侧是**稠密数据表格**（服务器列表：别名/地址/端口/传输协议/测速结果/延迟），表头可点击排序。
- 顶部工具条：添加服务器、批量测速（TCP/真连接）、按测速结果排序、导出分享链接/二维码、启用路由、系统代理状态切换。
- 底部**状态栏**常驻：当前系统代理状态（清除/自动配置/不改变）、HTTP/SOCKS 端口、上下行速率实时数字。
- 特点：信息密度极高、面向键盘流操作者；适合作为我们"节点表格视图"的参照，而非整体风格。

### 3. NekoBox（Android / PC）

- 下拉式主界面：顶部卡片显示当前配置与流量，节点列表带延迟测试（长按菜单），底部 Tab 导航（仪表盘/配置/日志/设置/关于）。对我们参考价值在于**移动端式卡片节点行 + 底部导航**的取舍——桌面端不采用底部导航，仅借鉴其"每节点行内联测速按钮 + 左滑式操作"的可发现性。

### 共性信息架构（三家的最大公约数）

| 区块 | Verge Rev | V2rayN | 采纳 |
|---|---|---|---|
| 仪表盘 | 首页卡片+速率图 | 底部状态栏数字 | ✅ 首页卡片（Verge 式） |
| 节点/代理 | 组+胶囊卡片+测速 | 稠密表格+批量测速 | ✅ 两者都要：卡片/表格**双视图切换** |

| 日志 | 级别过滤 | 级别过滤 | ✅ |
| 托盘 | 全功能菜单 | 有 | ✅ 保留并增强 |

## 技术路线评估与推荐

### egui 能力边界核对（逐项）

| 需求 | egui 现状 | 结论 |
|---|---|---|
| 左侧侧栏 + 卡片布局 | `SidePanel::exact`/`resizable` + `Frame::none().fill().rounding()` 自绘卡片 | ✅ 完全可行，圆角卡片用自定义 `Frame` 即可 |
| 暗色主题 | `Visuals` 全可定制：`dark_light::detect` 跟随系统，`ctx.set_visuals` 运行时切换 | ✅ 默认暗色即骨架，需覆盖色板 |
| 延迟色点 | `ui.painter().circle_filled(pos, r, color)` 一行搞定；色点+文本可封装 `latency_badge()` 组件 | ✅ |
| 速率曲线图 | `egui_plot`（官方维护）`Line`/`Legend`，数据来自现有 `TrafficMonitor` | ✅ 需加依赖 |
| 表格排序 | `egui_extras::Table`：虚拟化滚动、列宽拖拽、行选择；排序需自己按列 sort 状态数据（几十行代码） | ✅ |
| 拖拽排序 | egui 无内建 DnD；订阅卡片排序可用社区 `egui_drag_sort`/`easy-dnd` crate，或退化为"上移/下移"按钮（Verge 是网格 DnD，Hydra 订阅数少，按钮可接受） | ⚠️ 有折衷 |
| 微动画 | `Context::animate_value_with_time` / `animate_bool`，按钮悬停、面板展开、页面淡入 | ✅ 够用 |
| 图标 | `egui` 内置 `IconData` 自绘或 `egui_phosphor` 图标字体 crate（推荐，单色图标全家桶） | ✅ |
| 原生标题栏自绘 | `with decorated(false)` 可做 Verge 式一体化标题栏，但要自己处理拖拽区/最大化，**P2 可选**，不作为承诺项 | ⚠️ 可选 |

### 两条路线

**路线 A（推荐）：保留 egui 强化**
- 内容：上述能力项全部落地 + main.rs 模块化拆分（见下）+ 自定义主题。
- 优点：托盘(tray.rs)/二维码(qr.rs)/订阅(subscription.rs)及全部后台通道逻辑零重写；打包体积小（单 exe ~10MB）；无 Node 工具链；`Cargo.toml` 只加 `egui_plot`、`egui_extras`、`egui_phosphor`、（可选）`easy-dnd` 四个纯 Rust 依赖。
- 缺点：动画/视觉上限低于 Web 前端；拖拽排序需第三方 crate 或按钮降级。

**路线 B：Tauri 2 + Web 前端（直接复用 Verge Rev 的开源前端组件思路）**
- 优点：像素级复刻 Verge；生态里现成图表/表格组件。
- 缺点：需把 `Scheduler/TrafficMonitor` 状态通过 Tauri command+event 重新暴露（现有 egui 状态机全部作废）；托盘改用 tauri tray 重写；引入 Node/pnpm 工具链，构建复杂度翻倍；预计 15–20 人日且是重写而非重构。
- 结论：除非公司要求"和 Verge 一像素不差"，否则否决。可作为远期路线记录。

### main.rs（3236 行）模块化拆分方案（P0 执行）

```

├── main.rs            // 仅 eframe 启动 + app 装配（<100 行）

├── theme.rs           // 色板、Visuals 定制、字体配置、latency 色阶函数
├── components/
│   ├── mod.rs
│   ├── sidebar.rs     // 左侧导航（图标+文字，选中态）
│   ├── topbar.rs      // 顶栏：运行开关、系统代理开关、当前节点、模式
│   ├── card.rs        // 通用卡片 Frame 封装
│   ├── latency.rs     // 延迟色点/徽章组件
│   └── speed_chart.rs // egui_plot 上下行曲线封装
├── pages/
│   ├── mod.rs         // Page 枚举 + 路由
│   ├── dashboard.rs   // 首页仪表盘
│   ├── proxies.rs     // 代理/节点页（卡片+表格双视图）
│   ├── connections.rs // 连接页（P2，先占位）
│   ├── share.rs       // 分享（二维码/导入，从现节点页迁出独立成页）
│   ├── subscriptions.rs
│   ├── logs.rs
│   └── settings.rs
├── dialogs.rs         // 节点编辑/分享对话框等模态
```

拆分策略：按现有 `ui_overview/ui_nodes/ui_subscriptions/ui_settings/ui_logs` 五个函数（行号 2037/2161/2541/2988/3127）为切割线，`HydraApp` 状态字段按页归属下沉到 `pages/*::PageState` 结构体，页面函数签名统一为 `fn show(app: &mut HydraApp, ctx, ui)`；通道收割逻辑（proxy_start/health_check/node_test/sub_update 四个 receiver）集中在 `app.rs::poll_channels()`。

### 交互细节

- **测速**：行内 [测] 图标 → 复用现有 `node_test_receiver` 后台线程 → 立即显示 spinner（`egui::Spinner`）→ 完成后色点+毫秒淡入（`animate_value_with_time` 200ms）。「全部测速」逐个串行，进度显示在按钮内（`3/12`）。色阶：<200ms 绿 `#4ade80`，200–500ms 黄 `#facc15`，≥500ms 红 `#f87171`，失败红叉，未测灰。
- **拖拽排序**：P1 先用 ↑↓ 按钮（订阅卡片与表格行）；P2 引入 `easy-dnd` 做订阅卡片拖拽。
- **系统代理开关**：顶栏 iOS 式 toggle，开启时主色高亮 + 托盘 icon 变色；崩溃自动恢复逻辑不变。
- **托盘菜单**：`显示主界面 / ─ / 代理: 运行中✓(勾选切换) / 系统代理: 开✓ / ─ / 全部节点测速 / ─ / 退出`；tooltip 显示 `Hydra · 运行中 · hk-01 · ↓2.1MB/s`。
- **首启向导**：无配置时仪表盘位置显示四步引导卡（粘贴密钥→选证书→加节点→启动），完成后消失。
