# 安卓端日志与健康观测方案 v1

> 日期：2026-10-18 ｜ 状态：**已实施（A/B/C/D 三批一次交付，待真机验收）**
> 实施记录与验收数据见 §六 ｜ 基线：0.2.8-preview（日志页仅有 Kotlin 层启动步骤，Rust 数据面事件不可见）

---

## 一、现状问题（已核实）

| # | 问题 | 根因 |
|---|---|---|
| L1 | 日志只有「①读取配置 ②已加载 ③建立 TUN ④启动栈 ✓已接管」 | `EngineState.addLog` 只被 Kotlin 侧调用；**Rust 内核 tracing 事件不进应用日志页**（桌面端批次 A 已做桥接层，安卓没有对应实现） |
| L2 | 运行期（连接后）零日志 | 无周期性状态输出；内核的每连接事件、丢弃事件、异常都不落 UI |
| L3 | 无网/网络异常无感知 | 无健康探测、无 ConnectivityManager 监听；用户只能看到「已连接」假象 |
| L4 | 日志无级别区分/过滤/导出 | 安卓日志页只有纯文本列表（桌面已有级别徽章+文本/方向筛选+导出） |

## 二、方案（三层，按优先级）

### A. 内核事件桥接（基础，必做）
- Rust 侧新增 **日志环形缓冲**（同桌面 log_bridge 思路）：`hydra-android` 注册 tracing Layer，把事件写入 `Mutex<VecDeque<(level, msg, ts)>>`（容量 500，满丢最旧，字段化+掩码）
- uniffi 暴露 `vpn_logs_since(seq) -> Vec<VpnLogEntry>`（增量拉取，seq 游标）——复用 `vpn_stats()` 同款轮询模式
- Kotlin：现有统计轮询循环内一并拉日志（1s 间隔），去重后 append 到 `EngineState.logs`（上限 500）
- 效果：连接/断开、直连/中继决策、DNS、丢包、警告**全部可见**

### B. 周期健康探测（用户建议核心）
- 连接成功后启动探测循环：**默认 300s（5 分钟）**——与 Clash url-test 默认 interval 一致（sing-box urltest 默认 3m）；可配置 1m/3m/5m/10m/关。**另在连接建立与网络切换瞬间各触发一次即时探测**（5 分钟间隔对排障太稀疏）
- 探测内容（轻量、单次）：① DNS 解析 `223.5.5.5` 或系统 DNS ② TCP 连接节点（复用既有节点测试逻辑）③ 可选 HTTP HEAD 到 `http://connect.rom.miui.com/generate_204` 类端点（200/204 即通，字节数极小）
- 日志输出：`✓ 健康检查通过（DNS 12ms · 节点 89ms · HTTP 204 320ms）` 或 `✗ 健康检查失败（DNS 超时 · 节点可达 · HTTP 失败）`
- 失败策略：连续 2 次失败 → **升级为 warn 日志 + 通知栏提示「网络异常」**；连续 5 次 → 记录「疑似断网，建议切换节点/网络」；探测失败不影响数据面

### C. 网络事件与异常日志
- 注册 `ConnectivityManager.NetworkCallback`：网络切换（WiFi/4G）、丢失、恢复 → 写日志（`网络已切换到 WiFi` / `网络已断开` / `网络已恢复`）
- 数据面异常（已有 Rust 事件经 A 桥接）：`数据面退出`、`连续 5 次数据面退出`、`TUN 丢弃 UDP 包`、`通道重建` → 自动进日志
- 用户「没网」时的排障路径：日志里直接能看到 DNS/节点/HTTP 三段探测结果 + 网络事件时间线

### D. 日志页 UI 增强（对齐桌面）
- 级别徽章（Info/Warn/Error 着色）+ 级别过滤 + 关键字搜索 + 一键导出（复制/分享文件）+ 清空
- 自动滚动（新日志在底）+ 暂停滚动开关（排障时看历史）
- 沿用 HydraTheme 令牌，不新造组件

## 三、性能与边界

| 项 | 约束 |
|---|---|
| 探测开销 | 默认 300s 一轮（可配 1m/3m/5m/10m/关）；单轮 1 TCP + 1 DNS 查询 + 1 HTTP GET（≤1KB）；三项并行、各自 1.5-2s 超时；VPN 未连接不探测 |
| 日志内存 | Rust 环形 500 条 × ≤512 字符 + Kotlin UI 500 条 ≈ 可控上限（纯内存） |
| 日志持久化 | **已定稿：纯内存不落盘**——点击连接开始记录，服务停止/进程被杀即清空；仅用户主动「导出」时写 `files/exports/*.txt` |
| 安全 | 内核日志入环前统一脱敏（`mask_target` 语义：URL authority / IPv4[:端口] / 域名[:端口] / [IPv6]:端口 → 短哈希）；日志不上传；导出仅本机文件 + 剪贴板/系统分享 |
| 隐私 | 服务名/IP 与桌面同纪律：目标打码（短哈希保留端口）；端口与耗时保留用于排障 |

## 五、已确认决策与剩余项

已确认：
1. **探测间隔 = 300s**（对齐 Clash url-test 默认；可配）+ 连接/网络切换时即时探测
2. **日志纯内存不落盘**：点击连接即开始记录；划掉后台/服务停止即清空；存续期间可导出

已定稿（工程判断）：
3. **探测组合（比单一 204 端点更准）**：① 节点 TCP 直连（物理路径，判节点与载体网络）② **隧道内 DNS 查询**——Kotlin 用未 protect 的 DatagramSocket 向 223.5.5.5:53 发一次 DNS 查询（会进入 TUN → 中继 → 返回，**真实测隧道全链路**）；③ 可选 HTTP 204（`http://connect.rom.miui.com/generate_204`，国内可达；不用 gstatic——墙内必失败造成误报）。三项分别计时入日志，单项失败不误判整体
4. **失败处理：只告警不自动切节点**（v1）——连续 2 次失败 warn + 通知栏；连续 5 次提示「建议手动切换节点/网络」。自动切换留给调度层（避免与最低延迟调度策略冲突），并在连续 5 次失败时记录「如持续失败请检查规则文件/节点订阅」排障引导

## 六、实施记录（2026-10-18，A/B/C/D 一批交付，待真机验收）

### A. 内核事件桥接（Rust + Kotlin）

- **Rust**（`hydra-android/src/lib.rs`）：
  - `KernelLogLayer`（tracing Layer）承接内核事件 → 进程级环形缓冲
    `Mutex<VecDeque<VpnLogEntry>>`，容量 500、满员丢最旧；ERROR/WARN/INFO/DEBUG
    入环（DEBUG 保留「丢包/直连决策」等诊断，TRACE 丢弃），DEBUG/TRACE 降档为
    INFO 并保留 `[debug]`/`[trace]` 前缀。
  - 入环前统一脱敏 `sanitize_log_message`：URL authority / IPv4[:端口] /
    域名[:端口]（Known-TLD 白名单，避免误伤 `hydra.log`/`0.2.8`）/ `[IPv6]:端口`
    → `hydra_protocol::mask_target` 短哈希（端口保留）；字段化事件（` k=v`）
    逐值同样处理。
  - 订阅器在 `start_vpn` 首次安装（日志环 + 可选 `files/hydra.log` fmt 层）；
    新会话 `reset_vpn_logs()` 清空内容但 **seq 保持单调**（Kotlin 游标安全）。
  - FFI：`vpn_logs_since(seq: u64) -> Vec<VpnLogEntry>`（增量、seq 升序）与
    `VpnLogEntry { seq: u64, level: String, message: String, ts_ms: u64 }`。
- **Kotlin**：`HydraVpnService.startStatsPolling` 的 1s 循环内以 `lastSeq` 增量
  拉取；`EngineState.mergeKernelLogs` 按 seq 去重、整体倒序、封顶 500。
  用户点击连接开启新会话时清空；kill switch 自动重连**保留**断线原因与时间线；
  服务停止（含系统撤销）清空；进程被杀自然清零。

### B. 周期健康探测（Kotlin）

- 连接成功后启动循环：**默认 300s**，设置页可配 1m/3m/5m/10m/关
  （`HydraConfig.healthProbeSecs`，SecureStore 持久化，非法值归一化回 300s）；
  **连接建立首轮立即探测**，网络事件经 `Channel(CONFLATED)` 唤醒即时探测。
- 三项并行、独立计时（`HealthProbe.kt` 纯逻辑 + `HydraVpnService` IO 实现）：
  1. **节点 TCP 直连（物理路径）**：`Socket` 先 `VpnService.protect(socket)` 再
     `connect(node, 2s)`——绕过 TUN，测节点与载体网络；
  2. **隧道内 DNS**：**未 protect** 的 `DatagramSocket` 向 `223.5.5.5:53` 发一次
     A 查询（`www.baidu.com`，2s 超时），校验 ID/QR/RCODE/ANCOUNT——包进 TUN →
     UDP 中继 → 节点 → 返回，真实测隧道全链路；
  3. **可选 HTTP 204**：`http://connect.rom.miui.com/generate_204`（GET，1.5s
     超时，200/204 即通）；best-effort，**不参与整体失败判定**。
- 日志格式（已定稿）：
  - `✓ 健康检查（节点 89ms · 隧道DNS 12ms · HTTP 204 320ms）`
  - `✗ 健康检查失败（节点 超时 · 隧道DNS 失败）`（只列失败项）
- 整体失败 = 节点直连与隧道 DNS **同时失败**（单项失败不误判整体）。连续 2 次 →
  WARN 日志 + 通知栏「网络异常」；连续 5 次 → 「疑似断网，建议手动切换节点/网络」
  + 规则文件/订阅排障引导；恢复时清通知并记恢复日志。**不自动切节点**。

### C. 网络事件（Kotlin）

- `ConnectivityManager.registerNetworkCallback(INTERNET)`（过滤 `TRANSPORT_VPN`，
  否则只能看到自身 TUN）：WiFi/移动网络/以太网的可用、切换、断开 → 写日志并

### D. 日志页（Compose）

  + 清空 + 导出/分享；
- 导出写 `files/exports/hydra-logs-<时间>.txt`（纯文本、时间正序、带级别），并复制
  到剪贴板；「分享」走系统 `ACTION_SEND` 纯文本（不引入 FileProvider）；
- 全部颜色取 `HydraTheme` 令牌（四主题/动态取色兼容），关键控件带 TalkBack 语义。

## 七、实测噪声修复（2026-10-22，基线 06bf119 之后）

真机导出日志（500 条）暴露三类噪声，逐项修复并回归。

### 1. 桥接层 target 白名单（`hydra-android/src/lib.rs`）

`KernelLogLayer::on_event` 在级别过滤之后、字段提取之前增加 target 过滤
（`is_product_target`）：仅接受 `event.metadata().target()` 以 `hydra_` / `hydra-`
开头，或包含 `hydra_client` / `hydra_core` / `hydra_protocol` / `hydra_node` /
`hydra_android` 的事件；其余（hyper/tokio/tracing 等）直接 return。占用 500 条
日志主体的 `No cached session for DnsName("hydra.node")`、
`Not resuming any session`、`Using ciphersuite TLS13_AES_128_GCM_SHA256`、
`ALPN protocol is None`、`TLS1.3 encrypted extensions` 不再入环。

实现要点（核实 tracing-log 0.2.0 源码）：rustls 走 `log` crate，经 tracing-log
桥接后 **metadata target 恒为 `"log"`**，真实目标在 `log.target` 字段里——因此
白名单会把整座 log 桥（含 rustls 全部 debug）一并丢弃；已确认本产品代码没有
`log::info!/warn!/...` 调用（`hydra-protocol` 仅 `pub use log::*`，无使用方），
不会误伤自家日志。若未来本产品改走 `log`，需在此按 `log.target` 字段放行。

### 2. 连续重复消息抑制（×N 折叠，`hydra-android/src/lib.rs`）

`LogRing` 增加 `last_level` / `last_message`（原始消息，不含后缀）/ `last_count` /
`last_seq`，与环形缓冲同一把锁维护：

- 同一 `(level, message)` 连续出现：**不新增条目**，把最后一条的 message 更新为
  `原消息 ×N`（N = 重复次数，含首发）、ts 更新为最新；**seq 不变**（Kotlin 增量
  游标安全），上限计数自然增长（u64 饱和）；
- 出现不同消息或不同级别后计数重置；`reset_vpn_logs()` 一并复位折叠状态
  （否则新会话首条可能被误判为重复而更新已清空的 seq，导致该条丢失）。
- 效果：`TUN 规则直连: xxxxxxxx:443（bind 无）` 等连续刷屏折叠为一条。
- **边界（遗留）**：Kotlin 每秒按 `seq > lastSeq` 拉取，已下发过的条目在后续重复
  中只更新 Rust 环内内容、不会再次下发；同一秒内的突发在首次拉取时即显示最终
  `×N`。若要求跨秒实时刷新计数，需改拉取协议（游标回退 1 条并按 seq 覆盖合并）。

### 3. v6 动态地址池扩容 + 日志限频（`hydra-client/src/tun.rs` 等）

- **容量**：`.cargo/config.toml` 新增 `[env] SMOLTCP_IFACE_MAX_ADDR_COUNT = "40"`。
  smoltcp 0.11 的 `IFACE_MAX_ADDR_COUNT` 由 build.rs 读取（默认 2），feature
  `iface-max-addr-count-N` 只声明到 8，但 `SMOLTCP_<CONFIG_NAME>` 环境变量优先级
  更高（build.rs：`strip_prefix("SMOLTCP_")` 查表，`seen_env` 为真时忽略 feature）。
  动态池保持派生写法 `V6_DYNAMIC_SLOTS = IFACE_MAX_ADDR_COUNT - 3`：由 **5 槽
  （8-3）扩到 37 槽（40-3）**（目标 32 槽，父级决策取 40 容量留余量）。原先
  IPv6 站点多 CDN 地址时 3-8 槽易满，新 v6 连接丢 SYN、应用回落 IPv4。
- **日志限频**：“池满且全部活跃，放弃挂载”由 `debug!` 升级为 **`warn!`**（功能
  退化，用户应可见），每 **10 秒最多一条**：`AtomicU64` 记上次打印时刻，CAS 抢占
  打印资格；消息追加 **`累计 N 次`**（`AtomicU64` 累计真实放弃次数，含被限频吞掉
  的次数），每连接刷屏消失且退化程度可观测。
