# 部署运维评估（亲历式演练，2026-10-03）

视角：一名不熟悉本项目的运维，拿到一台空白 Ubuntu VPS，目标是"节点可用 + 客户端可连"。
方法：按 README 与源码逐步走查。结论先行：**全程 9 步，全部手工，零自动化，其中 4 步有明确卡壳点**。

## 一、部署步骤演练实录

| # | 步骤 | 依据 | 自动化程度 | 风险标注 |
|---|---|---|---|---|
| 1 | VPS 装 Rust 工具链（apt/rustup，1.70+）再 `cargo build --release` | README「快速开始」 | 必须手工 | **有坑**：VPS 上编译耗时且需 build-essential；README 未提供交叉编译/预编译产物说明。在 Windows 开发机编译后 scp 上去的二进制因 glibc 版本不匹配大概率跑不起来，且文档完全未提 |
| 2 | `openssl rand -hex 32` 生成 PSK | README 步骤 2 | 可自动化（一行） | 无坑，但需要自己记住"两端一致" |
| 3 | 上传二进制到 VPS（scp） | 无文档 | 必须手工 | 无坑但无指引 |
| 4 | `export HYDRA_AUTH_KEY=... && ./hydra-node 0.0.0.0:443` 前台启动 | README 步骤 3 | 必须手工 | **有坑①**：绑 443 需 root 或 `setcap cap_net_bind_service=+ep`（README 有一句提醒，但没给命令和 no-root 运行方案）。**有坑②**：shell export 的密钥进 history/进程环境，README 无任何告警 |
| 5 | 从节点目录取出 `hydra-node-cert.der`，scp 回客户端机器 | README 步骤 3 末尾一句话 | 必须手工 | **有坑③**：证书生成在**进程当前工作目录**（hydra-node/src/server.rs:26 `PathBuf::from("hydra-node-cert.der")`）。若第 6 步 systemd 没设 WorkingDirectory，服务从 `/` 启动 → 证书重新生成在 `/` → 客户端 pin 的旧证书全部失配，全员断连且日志不明显 |
| 6 | 配置进程守护 | **无任何官方方案** | 必须手工（自己写 systemd unit） | **有坑④（最大坑）**：仓库内 0 个 unit 文件/Dockerfile/一键脚本（已全库 grep 验证）。运维必须自己：写 unit、解决 `Environment=HYDRA_AUTH_KEY` 明文进 /etc/systemd/system（world-readable）、`Restart=always`、WorkingDirectory、日志去向 |
| 7 | 开 UDP 443 防火墙（ufw allow 443/udp） | README 仅建议端口，**无防火墙章节** | 必须手工 | 忘开 → 客户端超时，且节点把未认证流静默关闭，故障现象完全无日志线索，极难排查 |
| 8 | 客户端：编译 GUI/exe，设 `HYDRA_AUTH_KEY` + `HYDRA_NODE_CERT` 环境变量再启动 | README「GUI 客户端」 | 必须手工 | **有坑⑤**：GUI 无任何配置界面可填密钥/证书（hydra-client-gui/src/main.rs:406-411 直接从 env 读），Windows 小白要学"设置系统环境变量后重启 explorer"，README 只有一句"未设置时会报错"。exe 未签名 → SmartScreen 拦截，无文档 |
| 9 | 浏览器填 127.0.0.1:1080，curl 验证 | README 步骤 5-6 | 必须手工 | 无坑 |

## 二、部署维度逐项核查（现状证据）

### 1. 节点部署
- systemd unit / Dockerfile / docker-compose / 一键脚本：**全部没有**（`find` 全库验证，`.github` CI 也没有）
- 证书分发：纯手工 scp；分享链接 `hydra://`（share_link.rs）**不含密钥与证书**，无法一键导入，形同虚设
- 密钥轮换：无流程。换 PSK = 两端同时改 env 同时重启；换证书 = 删 cert/key 文件重启 + 重新分发，均无文档
- 开机自启 / 崩溃重启：无（全靠运维自写 unit）
- 日志：`tracing_subscriber::fmt::init()`（hydra-node/src/main.rs:68）仅 stdout，**无文件输出、无轮转**。前台跑 → 关 SSH 即停；systemd 跑 → 依赖 journald，无说明

### 2. 配置管理
- config/default.toml：**确认为死代码**。`hydra-node/src/config.rs` 的 `NodeConfig` 除定义外零引用（grep 全库验证），README 也自注"config/（占位，配置系统尚未实现）"。实际配置只能靠 11 个环境变量 + 命令行参数
- 多用户：不支持，单 PSK 单租户
- 端口/路径修改：改 env 即可，尚可；但默认证书路径相对 CWD 是升级隐患（见上）
- 升级流程：无文档。正确做法（替换二进制 + systemctl restart，证书文件保留）完全靠运维自己推断

### 3. 监控运维
- 健康检查端点：**没有**。节点是纯 QUIC/UDP（server.rs 只有 `endpoint.accept()` 循环），无任何 TCP/HTTP 监听，`curl /health` 不可能，负载均衡/拨测无法接入
- 流量统计：README 自认"模块存在但未接线，GUI 显示恒 0"；节点侧完全没有统计
- 排障体验：节点日志只有"New connection from x.x.x.x"和 Connection error；认证失败**静默关流**（这是反探测的设计意图，但副作用是"防火墙没开/密钥不一致/端口错"三种故障在两端日志里**看起来一样：什么都没有**）

### 4. 安全运维
- 防火墙指引：无 ufw/iptables 章节文档
- fail2ban/防扫描：无。认证失败的探测只被静默断开，没有计数/封禁/日志钩子可对接
- 密钥暴露面：README 主推 `export HYDRA_AUTH_KEY`（进 shell history）和 `--auth-key` 命令行参数（**进 /proc/pid/cmdline，同机所有用户可读**）。systemd `Environment=` 也 world-readable。无 "用 EnvironmentFile=root:600" 之类最佳实践

### 5. 客户端安装
- 无安装包、无自签名/代码签名流程；eframe 单 exe 本可绿色分发，但**必须先设两个环境变量**这一步毁掉绿色体验：双击 exe → 启动代理 → 报"未设置 HYDRA_AUTH_KEY"错误
- GUI 无首次启动向导：无密钥输入框、无证书文件选择器、无节点导入（分享链接不带密钥）；节点列表默认 `127.0.0.1:8080`，AppConfig 不持久化（main.rs:92-95，内存对象，重启即丢）
- 好的一面：Windows 系统代理一键设置/恢复已实现

### 6. 文档完备度
- README 快速开始可照做（6 步跑通最小 demo），但只覆盖"开发者前台试玩"场景
- 缺失：服务端部署手册（systemd/防火墙/日志）、客户端分发包与安装说明、故障排查 FAQ（尤其"连不上怎么区分是防火墙还是密钥"）、升级/轮换/备份（cert+key+PSK）手册

## 四、缺失清单（按"造成部署失败/卡壳"概率排序）

1. **无 systemd unit + 无守护方案**（必卡：前台跑、断连、崩溃不重启、证书 CWD 陷阱叠加）
2. **客户端 GUI 依赖环境变量 + 无配置持久化**（小白必卡：双击即报错）
3. **排障黑洞**：未认证静默关闭 + 无健康检查端点 + 防火墙章节缺失 → "连不上"三因一果，无日志可查
4. **无预编译产物/交叉编译指引**（VPS 编译慢、Win 编译 glibc 不匹配）
5. **密钥管理无最佳实践**（history / cmdline / world-readable unit 三处泄露面）
6. 证书分发与轮换无自动化（手工 scp 可忍，但 CWD 相对路径是隐形雷）
7. 日志无文件输出/轮转（journald 兜底尚可，但无说明）
8. config/default.toml 死代码误导（运维会以为能改 toml）

## 五、补齐建议（优先级 × 工作量）

| 优先级 | 项 | 内容 | 工作量 |
|---|---|---|---|
| P0 | 部署套件 | 仓库内提供 `hydra-node.service`（EnvironmentFile=/etc/hydra/env, WorkingDirectory=/var/lib/hydra, Restart=always, AmbientCapabilities=CAP_NET_BIND_SERVICE）+ install.sh + 防火墙/排障章节 | 0.5-1 天 |
| P0 | GUI 配置持久化 | 密钥/证书路径/节点列表做成界面字段 + 存文件（confy 或 %APPDATA%），消灭 env 依赖；顺带首启向导 | 1-2 天 |
| P0 | 排障能力 | 最小 HTTP 健康端点（可选开）+ `--verbose` 下记录"认证失败计数"；README 排查决策树 | 1 天 |
| P1 | 分发 | GitHub Actions 交叉编译（x86_64-unknown-linux-musl + windows-msvc）release 产物 | 1 天 |
| P1 | 证书/密钥运维 | cert 固定到 /var/lib/hydra；`hydra-node fingerprint` 子命令打印指纹供比对；轮换文档 | 0.5 天 |
| P2 | 接线或删除 config/default.toml；Docker 镜像；fail2ban 指南 | 1 天 |
