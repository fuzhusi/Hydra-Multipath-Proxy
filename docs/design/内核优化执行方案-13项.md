## 第一批（速胜）

### #1 温连接 stale 快速回退

- **动机**：checkout 到半开死连接时 `request_target` 挂 `RESPONSE_TIMEOUT=20s`
  才弃连（tcp_transport.rs:512），而温路径正常 1 RTT（100-200ms）、冷回退
  ~500ms——最坏尾延迟放大 40-200 倍，且发生在用户等待首字节的关键路径上。
- **设计**：`request_target` 增加超时参数（新函数 `request_target_with_timeout`
  或参数化）；proxy.rs open_target 的**池化分支**用 ~8s 包裹（≈3 RTT + 目标拨号；节点目标拨号预算 15s——
  5s 会把健康慢目标 3-15s 误判 stale 后冷路径重拨同一目标，最坏多付一整
  轮；8s 覆盖绝大多数拨号，env `HYDRA_WARM_TIMEOUT_SECS` 可调），冷路径
  维持 20s 不变。失败语义不变：弃连落回既有冷握手路径，不
  参与评分与故障切换。
- **验收**：新单测（stale 温连接在短超时内回落冷路径成功）；既有温命中/
  e2e 回归全绿。

### #5 v6 AnyIP：has_ip_addr 短路 + protected 集增量维护

- **动机**：每个入站 v6 TCP 包（≥99% 为已建立流的数据/ACK）全量遍历
  SocketSet（≤512）构建保护 HashSet ≈ 5-20μs，而 `ensure_v6_dst` 首行
  `has_ip_addr` 命中即返回——白做；20k v6 pps ≈ 0.1-0.4 核/秒。
- **设计**：① 入口先 `has_ip_addr(dst)` 命中即 return（语义无损：地址已在
  接口上无需保护检查）；② protected 集增量维护**降级为可选**：挂钩点必须是 SocketSet 条目
  增删边界（"流登记插入"会重新引入 tun.rs:1975-1981 记录的握手期误
  淘汰竞态——poll 建 socket 与 flows.insert 之间隔一轮投喂）；①之后
  SocketSet 遍历仅在"新目标首包"发生，②收益已小，实施时单独评估。
- **验收**：既有 v6 保护单测（握手期保护语义）全绿；新增增量维护一致性单测。

### #2 Android fd 路径：专职读写线程 + 有界通道

- **动机**：每包 2-3 次 spawn_blocking 往返（各 5-15μs）+ 3 次堆拷贝 ≈
  15-50μs/包；更严重的复合缺陷——run_stack 的 select 10ms tick 丢弃 recv
  future 后，FdTransport 孤儿阻塞任务仍持 Mutex<File> 读走下一包且结果丢弃：
  **稀疏流量下每 tick 吞一包**（TCP +1 RTT 尖刺，UDP 中继永久丢包）。
- **设计**：FdTransport::new 启动两个 std::thread——读线程循环 read(1504B
  直读自有缓冲) → 有界 async-channel(256) 发送（满即停读 = TCP 窗口背压）；
  写线程从通道 recv → write_all。`PacketTransport::recv/send` 改纯异步通道
  收发，**trait 不变、run_stack 零改动**。
  **停机语义（评审 P0 修正）**：读线程阻塞在 tun fd `read()` 上，直接
  join 会死锁——fd 所有权与 JoinHandle 分离：停机时先关闭 fd（dup 原始
  fd 或持 OwnedFd），`read()` 立即返回 EBADF/EOF 退出，再 join。否则
  `stop_vpn` 的 3s shutdown_timeout 必然超时弃置 runtime，逐次泄漏 fd
  与线程。
  **验收补充**：合成 fd（管道）吞包修复行为测试——tick 丢弃窗口内到达
  的包必须经通道完整交付。
- **验收**：Android 冒烟（cargo check android target + gradle 构建）；本地
  GUI 回归不受影响（PacketTransport trait 兼容）。

## 第二批（运维基础 + 协议红利）

### #4 节点 Metrics v2

- **动机**：6 个计数族无法回答吞吐（字节只在连接关闭 info 日志）、延迟归因
  （四段建连延迟无测量）、UDP fd 悬崖预警（无会话 gauge）；conn_rejected
  不分原因 → 告警规则不可写。
- **设计**（metrics.rs 扩展，零新依赖）：
  1. `hydra_bytes_in/out_total`：pump 已有 total 计数处 fetch_add；
  2. 四段延迟直方图（TLS/Noise/DNS/target-connect）：Instant 测量点接入手写
     固定对数桶（`# TYPE histogram` 渲染 ~15 行/族）；
  3. `hydra_udp_sessions_active` gauge（会话进出守卫）+ datagram 转发/丢弃
     计数（overlimit_drops 由连接级日志改全局原子）；
  4. `conn_rejected` 拆 4 个原因 counter（per_ip/capacity/tls/auth）；
  5. 目标 top-N：有界 1024 条 LRU（短哈希 label）+ /metrics 快照渲染。
  热路径统计一律连接内累加、关闭时汇入。
- **验收**：render 单测扩展（新族渲染正确）；本地 curl /metrics 目检。

### #3 握手 RTT 压缩：地址帧与 confirm_c 捎带（5RTT→4RTT）

- **动机**：confirm_c 与地址帧无数据依赖（msg2 的 AEAD tag 已完成对节点的
  PSK 认证），但当前代码在 confirm_s 之后才发地址帧——白付 1 RTT。
  100ms RTT 下冷建连 500ms→400ms（-20%）；hydra-fetch 每轮块、TUN 冷流、
  温池 replenish 全部受益。
- **设计**：客户端单侧改动——`handshake::client_side` 增加可选捎带载荷：
  write `[confirm_c][地址帧]` 合并一次写，随后顺序读 `[confirm_s][2B 应答]`。
  **节点零改动即兼容**（旧节点写完 confirm_s 后本就立即读目标帧，字节已在
  内核缓冲——TCP 字节流语义下推理可靠）。安全性不变：目标串只暴露给已通过
  msg2 tag 认证（持 PSK）的对端；confirm_s 校验失败仍整体弃连。
  **影响面（评审补）**：`client_side` 第二调用点 nat.rs:427（P2P 侧）同步
  适配；捎带版无法复用 `connect_channel`（刻意停在发帧前）——冷路径
  `connect_target` 需重构为"握手+捎带"一体；兼容矩阵在节点不变前提下退化为
  新旧客户端两组。
- **验收**：新旧客户端 × 新旧节点 4 组合兼容矩阵单测；既有握手单测全绿。

### #7 弹性温池：cap 2 → 动态 clamp(2, 近期峰值, 8)

- **动机**：cap=2 使 B 条并发突发命中率 = 2/B（B=30 页面加载时 7%），
  93% 流量付冷建连且每突发对节点产生 B-2 次握手风暴；节点余量充足
  （per-IP 256 / 全局 1000）。
- **设计**：ChannelPool 每节点维护 recent_peak（60s 滑窗内 checkout 未命中
  次数 EWMA）；checkin/replenish 的 cap 改 clamp(BASE=2, peak, MAX=8)。
  TTL 维持 60s（真实存活约束是节点 300s idle 看门狗；客户端 keepalive
  首探 60s 与 TTL 贴边问题改为把 keepalive time 降至 30s 解决）。
  **容量注记**：共享 NAT 出口下 cap=8 × 客户端数可能逼近节点 per-IP 256
  （约 32 客户端/节点）——cap 上限 8 保持，超密部署靠 env 收紧。replenish 成功/
  失败顺带回灌 scheduler 作被动健康信号（可选附注）。
- **验收**：单测（峰值抬升/衰减/水位变化）；温命中 e2e 回归全绿。

## 第三批（节点热路径与资源面）

### #6 节点 DNS 共享缓存 + 全局解析并发闸 + 双族并行 Happy Eyeballs

- **动机**：TCP 路径每连接冷 getaddrinfo（无缓存无限流）：域名透传负载下
  每新连接多 10-200ms；解析器故障每连接烧 5s 且可瞬间打 512 个 blocking
  线程；逐候选串行使最坏失败路径吃满 20s（顶满客户端预算）。
- **设计**：① 共享 DNS 缓存（HashMap<String, (Vec<SocketAddr>, Instant)>，
  统一 60s 上限（getaddrinfo 不暴露记录 TTL）、负缓存 10s、1024 条 LRU；
  缓存存已过 SSRF 过滤的地址）；② 全局解析 Semaphore（64 并发）+ 排队超时；③ 首两候选
  250ms 错峰并行 connect，先到先用，SSRF 逐候选过滤语义不变。UDP 路径
  DnsCache 切到同一实现（单源化）。
- **验收**：缓存 TTL/负缓存/容量单测；SSRF 测试全绿；Happy Eyeballs 并行
  建连单测。

### #8 pump 去定时器化：连接级 watchdog 替代每读/写 timeout

- **动机**：每 16KB 全双工数据 ≈ 4 次 Sleep 堆分配 + 定时轮注册/摘除；
  10Gbps 聚合 ≈ 32 万次 timer 操作/s + 16 万次分配/s 纯开销（几个百分点
  CPU + 分配器压力）。
- **设计**：每连接 spawn 微型 watchdog task：持 last_read/write 原子（pump
  成功读写时更新），按 min(idle/4, 1s) 周期检查 idle/寿命，超限经既有
  Notify/AtomicBool 通路唤醒两 pump 收尾；pump 循环改裸 read（select 仅留
  peer_exit）。写超时 60s 同样由 watchdog 检查（记录 pending write 起始时刻）。
- **验收**：既有 pump 单测（共享时间戳不误杀/寿命到期活跃也关闭）全绿
  为门；**写超时单测为新增**（现有 pump 仅 2 测试）；注明 idle 现仅由读
  刷新（写不刷新）——语义保持；pending-write 原子用 release/acquire，
  写完成瞬间的良性误判窗口容忍（注释）。

### #9 UDP 会话瘦身：分层接收 buf + 字节预算队列 + 全局会话/socket 上限

- **动机**：每会话急切 64KB 接收 buf → 最坏面 256 会话/连接 × 1000 连接 ≈
  **16GB 用户态**（远超已知评审的 268MB）；fd 悬崖更先到——默认 ulimit 1024
  下全节点仅 ~900 个会话即 bind 失败，应用层无全局预算，失败仅 debug 日志。
- **设计**：① 接收 buf 起步 4KB，截断检测经 socket2 `SockRef::recv_from_vectored`
  （跨平台 `RecvFlags::is_truncated()`：Windows 走 WSAEMSGSIZE 映射、Unix
  走 msg_flags）升档 4K→16K→64K，tokio 侧 `readable().await` + WouldBlock
  重试集成（DNS/QUIC 负载下每会话 70KB→~10KB）；② 上行队列预算改
  按字节（128KB/会话）替代 16×任意大小；③ 进程级全局 UDP 会话数 + 字节预算
  两个 AtomicU64，超限拒绝新会话并下行 close（通路已有），bind 失败 debug→
  warn+counter；④ now_ms() 统一单调钟（与 tcp_server mono_ms 同源）。
  共享单 socket+四元组分发列后续大改（本轮不做）。
- **验收**：分层 buf 单测（截断升档）；全局预算拒绝→close 帧单测；
  UDP e2e 回归全绿。

## 第四批（平台调优与上限补全）

### #10 TCP Fast Open 出站（TCP_FASTOPEN_CONNECT，平台门控）

- **动机**：冷/温握手建连省 1 RTT；与 #3 叠加冷建连 5RTT→3RTT（-40%）。
- **设计（评审 P0 修正）**：socket2 0.6 **无 TFO API**——客户端侧 raw
  `libc::setsockopt(TCP_FASTOPEN_CONNECT)`（Linux/Android 门控，Windows/
  macOS 回退），env `HYDRA_TFO=0` 关闭。**节点侧必须同步**：listen socket
  设 `TCP_FASTOPEN` + sysctl `net.ipv4.tcp_fastopen≥2`（客户端单侧对未启用
  节点永远走 cookie 请求回退 = **零收益**）；部署文档同步更正。节点侧代码
  改动 +0.5~1 人日。
- **验收**：平台门控单测；回退路径测试（未启用节点 = 现状行为）；部署
  文档含 sysctl 与验证方法。

### #11 调度评分量纲归一化 + EWMA

- **动机**：loss 项最大 -0.2 ≈ 无效（50% 丢包仅扣 0.1 分）、load 权重 0、
  名义权重与实际影响脱节（100Mbps/300ms 节点负分）；被动吞吐整值替换无
  平滑 → best 节点以 30s 节拍振荡；Online→Degraded 检测 90s+。
- **设计**：① 评分改无量纲效用和：`w1·(1-exp(-bw/100)) + w2·(1/(1+lat/200))
  + w3·(1-loss) + w4·(1-load)`（权重 0.4/0.3/0.2/0.1 起步）；② 实测带宽/
  延迟 EWMA（α≈0.3）替代整值替换；③ 数据面失败触发对该节点即时定向探测
  （90s→<1s）。
- **验收**：固定节点集排序对拍单测；HYDRA_SPEEDTEST/PROBE_INTERVAL 语义
  兼容。

### #12 上限补全：目标 socket keepalive/user_timeout + 可选每连接带宽限制

- **动机**：死目标连接最坏 300s 才被 idle 兜底（钉住 permit+fd+TLS 状态
  ~100KB）；无带宽上限时单连接可独占出口。
- **设计**：① socket2 给目标 TcpStream 设 keepalive（idle 60s/interval 10s）；
  user_timeout 需 socket2 feature `all` 且仅 Linux/Android（Windows 无 API
  ——平台门控跳过或 raw setsockopt），死目标 ~90s 回收；② 可选 `HYDRA_PER_CONN_MBPS` token
  bucket（连接级 AtomicU64 令牌 + 惰性补充），默认关闭零开销。
- **验收**：keepalive 设置单测；token bucket 限速单测（固定速率上下界）。

## 不做（#13 v4 帧化多路复用——负向决策存档）

**维持不做**。量化依据：温池已把主路径压到 1RTT/流，mux 边际收益仅
1RTT→~0.2RTT 摊销，只对 TUN 千流级短流突发有可感差异——而 #7 弹性温池以
1/10 成本覆盖其大半。既有否决依据仍成立：TLS-in-TLS 指纹检测模型（单连接
内规整多流比多连接更易指纹化）、跨境高丢包下 TCP 单流 mux 队头阻塞负优化
（Xray/sing-box 社区共识）、1-2 人周成本。

**重开触发条件**（写入已知限制）：实测 TUN 并发建连风暴使节点握手 CPU/
连接额度（1000 上限）成为瓶颈；或出现 1000+ 并发短流工作负载。

设计草案存档（备用）：流首版本字节 [0x04] 协商（旧节点静默关流→客户端按
节点缓存能力回落 v3；禁用 ALPN 协商以保护 chrome 指纹伪装）；帧集
OPEN/DATA/FIN/RST/PING/GOAWAY（FIN 为 hydra-fetch 半关闭透明性硬前提）；
流控 = 每流 256KB 信用 + 通道全局窗口；节点逐流保留裸转发 pump。

## 执行降级记录（code review 回顾后如实标注）

- **#2 停机语义重写**：dup fd close 不唤醒阻塞 read（共享 open file
  description）——最终实现为 poll(2) 100ms 轮询（读线程）+ recv_timeout
  （写线程），join 上限一个周期；"close 副本唤醒"路线经内核语义核实不可行；
- **#10 客户端 TFO 撤下**：TCP_FASTOPEN_CONNECT 有缓存 cookie 时 connect(2)
  返回 EINPROGRESS 且 tokio TcpSocket::connect 的 poll_writable 对
  TCP_SYN_SENT 不报就绪 → await 永久挂起（内核源码核实）——仅保留节点侧
  listen TFO，客户端撤下并记录重开条件；
- **#8 "去定时器化"降级为读唤醒常数化**：watchdog task/裸 read 未实施，
  timeout(1s, read) 保留——量化宣称（32 万次 timer 操作/s）不成立，实际
  收益为消除变预算计算与抖动；
- **#9 ②③ 降级**：字节预算队列与全局会话/字节上限未实现（fd 悬崖动机
  未缓解），分层 buf 落地；后续批次补；
- **#11 ②③ 降级**：EWMA 平滑与失败定向探测未实现，仅评分公式落地；
- **#3 影响面**：nat.rs 第二调用点走无捎带薄封装（零改动确认）。

## 执行纪律

1. 每批一个 commit（批次内全绿才进下一批）；全部完成后统一 code review
   （独立评审员全项核查）→ 修复 → 一次推送；
2. 每项必须有验收测试（本方案各节"验收"即测试清单）；
3. 既有语义守护：P3-8 建链状态机、半关闭排水、SSRF 过滤位置、温池尽力
   而为语义（弃连回退不碰评分）——改动触碰这些点时以现有单测为回归门；
4. 批次推进中发现前批缺陷：记录并修在同批，不跨批携带。
