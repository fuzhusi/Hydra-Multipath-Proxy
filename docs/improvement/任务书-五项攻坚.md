## T3 V3.2 Noise-PSK 握手 v2 ｜ Team-H

**目标**：静态 HMAC token 升级为前向安全握手（V3 方案 §4 V3.2 的可交付收敛版）。
**设计**：
- **前置**：rustls 0.23 + ring 0.17 全工作区升级（Phase B-6），API 迁移（Certificate→pki、with_safe_defaults 移除等）
- **版本字节**：流首字节 `0x00`=legacy v2（node 补读剩余 63B 还原 token，兼容不变）、`0x03`=v3 握手
- **握手**：snow `Noise_NNpsk2_25519_ChaChaPoly_SHA256`，PSK=现有 HYDRA_AUTH_KEY 解码值；msg1（客户端 e）→ msg2（服务端 e,ee,psk）→ 双方持传输密钥对
- **数据面不变**：握手提供应用层认证+抗重放+前向安全；数据仍由 QUIC/TLS 保护（不重加密）
- **通道绑定**：优先 rustls exporter（`export_keying_material` 混入握手 hash）；不可用则绑证书指纹（如实标注）
- **rekey 推迟** V3.3（如实标注）；`HYDRA_AUTH_MODE=auto|v2|v3`（默认 auto 双栈互通）
- 帧协议/通道模式（0x01）在 v3 握手后沿用
**文件所有权**：全部 `Cargo.toml`、`hydra-protocol/src/handshake.rs`（新）、`hydra-client/src/{transport.rs, pool.rs, proxy.rs(认证调用点)}`、`hydra-node/src/{handler.rs(认证段), server.rs, cert.rs}`。
**验收**：① snow 标准测试向量过 ② 双栈互通集成测试（v2 客户端↔v3 节点、v3 客户端↔v2 节点、v3↔v3）③ 重放整段握手字节被拒 ④ 拨系统时钟 ±1h 不影响 v3（去时间窗依赖）⑤ 全量回归绿 ⑥ rustls 无双版本并存。
**降级授权**：rustls 0.23 升级破坏面超预期 → 保 0.21 + snow 握手（绑证书指纹替代 exporter），如实标注。

## T4 跨节点字节级聚合 ｜ Team-R

**目标**：兑现"多节点带宽叠加"的终极形态（入口节点汇聚架构）。
**设计（入口节点汇聚）**：
- 入口节点（评分最高者）持有目标 TCP（现有 channel creator 机制）
- 客户端上行帧轮转分发到 **N 个节点的全部数据流**；非入口节点收到帧后，以**标准客户端身份**（完整认证）向入口节点开数据流 `[0x01][cid][role=1]` 转发帧——入口节点现有 channel 机制直接吞并这些流，零节点间新协议
- 节点间信任 = 复用同一 PSK 认证（非入口→入口即标准客户端握手；v3 落地后即 v3 握手）
- 客户端：`HYDRA_CHANNELS` ≥2 且 `HYDRA_AGGREGATE=1` 且 ≥2 Online 节点时启用；上行 ack（V3.4 v2）经原路回流
- 下行：入口节点分发 TCP 数据到全部已附着的流（含来自非入口节点 relay 的流）——现有机制天然支持
**文件所有权**：`hydra-node/src/handler.rs（channel 段 relay 标记）`、`hydra-client/src/{aggregate_stream.rs, aggregate.rs, proxy.rs(入口)}`、新增测试。
**验收**：① 双节点 64MB 聚合校验和逐字节相等且两节点均承载流量 ② 杀 1 节点：新连接不中断 ③ 未启用时路径逐位不变 ④ 256MB 压力（复用 V3.4 v2 ACK 机制）
**降级授权**：多节点下帧丢失竞态复现且无法修复 → 只交付节点间 relay 协议 + 如实报告（字节级聚合标注继续实验性）。
