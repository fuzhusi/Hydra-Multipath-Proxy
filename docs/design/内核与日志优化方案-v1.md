## 二、优化方案（两批，借鉴开源 + Rust 等价实现）

### 批次 A：日志系统统一与工程化（预估 4-5 天）⭐ 先做（零行为风险）

| # | 项 | 方案（借鉴来源） | 验收 |
|---|---|---|---|
| A1 | **内核 tracing 全链路桥接** | hydra-core/hydra-node 统一 tracing 事件（字段化：target/direction/bytes/duration_ms）；GUI 挂自定义 tracing Layer 把内核事件转进日志页（消 L3；借鉴 tracing Layer 订阅者模式） | GUI 日志页能看到「直连成功/通道建连/会话回收」等内核事件 |
| A2 | **GUI 日志换 VecDeque** | `VecDeque<(LogLevel, String)>` + push_back/pop_front（消 L1 的 O(n)）；容量常量化 | 单测：容量边界不搬移 |
| A3 | **文件持久化 + 轮转** | 节点侧：tracing-appender `non_blocking` + daily rotation（**WorkerGuard 防丢失**——借鉴其退出丢日志教训）；GUI 侧：可选「自动保存日志到文件」（默认关，开 = 追加写 + 单文件 10MB 轮转） | 节点日志文件按日滚动；GUI 开关生效 |
| A4 | **运行时级别热调** | 设置页日志级别下拉（error/warn/info/debug/trace）→ tracing EnvFilter 运行时 `reload::Layer` 热更新 + 配置持久化（消 L5；借鉴 EnvFilter 热调） | 拉到 debug 后内核 debug 事件实时出现在 GUI |
| A5 | **热路径日志惰性审计** | tracing 字段化替代 format!；高频事件采样（每 N 万包 1 条）或降为 trace 级（消 L6） | 热路径无无条件 format! |

### 批次 B：内核数据面（预估 5-7 天，依赖基准先行）

| # | 项 | 方案（借鉴来源） | 验收 |
|---|---|---|---|
| B0 | **criterion 基准先行**（硬前置） | udp_relay 吞吐基准 + 分配计数（`#[global_allocator]` 计数分配器统计每包分配次数/字节） | 基准数字入 docs；后续每项优化以基准对比验收 |
| B1 | **UDP 回包缓冲复用** | build_udp_reply 改就地构造：session 持有出向 scratch（BytesMut 复用），或返回写入调用方缓冲（消 D1；借鉴 quinn「缓冲所有权契约」） | 基准：稳态分配次数 0 |
| B2 | **checksum16 单遍化** | 累加器结构（免拼接 Vec，逐段 feed 后 finalize）（消 D4） | 与现实现等价性测试（固定样例） |
| B3 | **udp_relay 帧构造复用** | 帧头预构造 + payload 单次拷贝；或 write_vectored 聚合（消 D2；借鉴 mihomo 写聚合） | 基准：帧构造分配 0 |
| B4 | **连接元数据零分配** | opener 链路 target 改 SocketAddr 结构传递（String 仅展示层 Arc<str>）（消 D3，统一路由遗留闭环） | 每连接分配 0（基准断言） |
| B5 | **UDP 下行写聚合** | 攒批：≤1ms 或 ≤2×MTU 即 flush（借鉴 mihomo 批量写） | 吞吐基准对比 |
| B6 | （评估）泵缓冲池化 | 先看 B0 基准中内存占比，占比低则不做 | 评估结论入文档 |

## 三优先级对应

- **性能**：批次 B 全部 + B0 基准（优化以数据说话）
- **安全**：缓冲复用引入的所有权/生命周期风险 → 所有权单测覆盖（B1/B3 强制）；tracing 字段化顺带解决日志脱敏一致性（字段级脱敏函数单点化）
- **美观**：日志页级别筛选已有；新增级别下拉/持久化开关沿用既有设置行样式（不新造组件）

---

## 三、不做什么（本轮边界）

- 不换 TUN 栈（gVisor/system 双栈评估为架构级演进，单独立项）
- 不做多路径帧复用（依赖已搁置的多路径聚合，随 RFC v2 §6.3#15 重评估）
- 不做日志远端上报（隐私边界，本地文件足够）
- GPL 项目（sing-box/mihomo）**零代码复制**——只借鉴设计思路，全部 Rust 等价自研

## 四、验收总门

- criterion 基准数据：批次 B 每项「分配次数/吞吐」前后对比表
- cargo test --workspace 全绿；clippy 零告警
- 日志：内核事件进 GUI ✓ / 级别热调生效 ✓ / 轮转文件 ✓ / 退出不丢（WorkerGuard）✓
- 全程行为兼容：OFF/默认配置下与基线一致（分流/代理语义不变）

## 五、方案评审结论（已合入，评审全文见提交记录）

**无 P0。批次 A 全部可行；批次 B 两处修改、一处降级、一处补漏：**

1. 批次 A 硬约束：GUI main.rs:246 单一 fmt().init() 必须重构为 registry 一次性组装（fmt stderr + reload(EnvFilter) + GUI 环 Layer），此后全进程不得二次 init（GUI 进程内起代理，无双重 init 冲突——已核实）
2. A2 VecDeque 标注「顺手修」（LOG_CAPACITY=1000 搬移量级可忽略，非性能项）
3. A3 追加写轮转按时间（tracing-appender daily）；10MB 大小轮转需自包一层，预留 +0.5 天
4. **新增 A6：连接结束日志模式**（建立/关闭各一条、带路径/字节数/时延——调研 #14，0.5 天，诊断价值高）
5. 批次 B：B1+B2 合并为一个提交（回包就地构造 + 单遍校验和，消每包 2 次分配）；B4 降级为 B0 后评估项（ChannelOpener 跨 crate 契约触面 ~10 处，收益太小，改走 TUN 侧保留原始 SocketAddr 旁路）；B5 改分平台评估项（wintun batch 明确，Linux 需 GSO 先测）
6. 补充：日志页顺带加「按 target/方向筛选」（字段化后数据具备，0.5 天）
7. 工作量：A 4-5 天成立（A2 让出余量给 A5/新增 A6）；B 压缩为 4-6 天，余量给 B0
