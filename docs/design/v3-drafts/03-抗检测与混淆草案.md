## 0. 先回答老板的问题：自研协议在抗检测上是加分还是减分？

结论：**取决于"自研"暴露在哪一层。**

| 自研暴露位置 | 判定 | 依据 |
|---|---|---|
| 密文之外的线缆格式（ALPN、Magic、固定前缀、心跳周期） | **确定性减分** | QUIC Initial 密钥公开可解（F1/F2）；任何明文可识别结构 = 一条零误报 DPI 规则（F15 教训） |
| 加密层之内的协议语义（stream 复用、认证、调度算法） | **中性** | 被动观察者本来就看不到 |
| 自研的流量整形能力（padding、去周期、去相关） | **加分** | 让统计特征更接近正常流量 |

"协议要有自己的东西"的正确落点是**内层语义与调度算法**，而不是线缆格式。任何以"自研"为名出现在密文之外的结构，都是在给自己发身份牌。

## 1. 核心矛盾："自研线缆格式"的三种形态

### 1.1 可检测性对比

| | a) 随机字节流混淆 | b) 伪装标准协议 | c) 明文自研格式 |
|---|---|---|---|
| 代表 | Hysteria2 Salamander、SS2022 | 本项目当前路线（QUIC+h3）、ShadowTLS/restls/REALITY | RFC §8 Packet（magic 0x48594452） |
| 原理 | 每包变换为均匀随机字节 | 融入某标准协议的完整形态 | 明文 Magic+帧 |
| 特征匹配 DPI | 完全失效 | 失效（前提：形态做像） | 一条规则全量精准识别 |
| 白名单式审查 | **"不明加密 UDP"即靶子**（审查模型=只放行认识的） | 可融入白名单 | 靶子 |
| 主动探测 | 无法判型（但也无真站可装） | 做像了→探测者看到真站/404 | 确定性签名 |
| 统计审查 | 高熵+长寿命无结构 UDP，组合特征可疑 | 做像了→与正常流量同分布 | — |
| 维护代价 | 低（一层包变换） | 高（证书/指纹/行为面/探测伪装全链条） | — |

关键洞察：**b 的可检测性来自"做得不像"，而非"伪装"这个选择本身**。a 在黑名单模型（特征匹配、UDP QoS 限速）下是最优解，在白名单模型（全封锁非白名单、QUIC 指纹白名单）下反而最脆弱；b 在两种模型下都不差，但需要持续投入把形态做像；c 在任何模型下都是自杀，**绝对禁止**。

### 1.2 适用场景与组合建议

**推荐：默认 b（伪装模式）+ 可选 a（混淆模式，逃生舱），永久禁止 c。**

- **masquerade 模式（默认）**：QUIC/UDP 443 + ALPN=h3 + 真证书/SPKI pin + 认证失败静默 + h3 伪装响应。覆盖 90% 场景，对齐 03 报告短期项 1–7 与中期项 8。
- **obfs 模式（逃生舱）**：在 QUIC 外再包一层随机化（Salamander 式），用于"UDP 非白名单即封"或"QUIC 指纹白名单"的重度审查地区——此时白名单里根本没有我们的位置，随机流是唯一选项。两模式**互斥**，由配置/分享链接显式选择，同一连接绝不叠加。
- **c 的禁令**：协议内部帧结构（未来多路聚合的 chunk 头）只能存在于 QUIC stream 密文之内，外层永远呈现为 a 或 b。

## 2. 报文形态设计（obfs 混淆层）

### 2.1 每 UDP 报文变换

线缆格式：`[8B salt][XOR_keystream(QUIC 报文)]`，正/逆变换各一次流密码运算。

- **密钥来源**：`obfs_key = HKDF-SHA256(PSK, salt="hydra-obfs-v1", len=32)`；每包 keystream = `ChaCha20(obfs_key, nonce=salt)`，salt 每包随机（≥8B）。无密钥者重放/伪造的包解出垃圾但仍表现为随机——混淆层不承担认证，认证在内层 QUIC。
- 参照 Salamander（每包 XOR PSK+salt 派生 pad），我们用 ChaCha20 keystream 替代 pad 展开：成本相同，消除 pad 复用风险。
- **混淆≠加密**：机密性由内层 QUIC/TLS 承担，混淆层只负责"字节均匀、无结构"。
- **随机 padding 不放混淆层**（两层变形叠加会产生新规律），padding 放 QUIC 层（quinn 已支持帧/报文 padding），首包与短控制包长度归一化。
- **长度分布**：混淆层不改变长度（与 Salamander 一致）；QUIC 层可选三档离散 padding（1200/1350/1500）+ 抖动，弱化"包长↔内容"映射。
- **时序特征**：keepalive 抖动 30–120s（现有 7–12s 再放宽）；ACK/pacing 交给 QUIC 栈默认值，不自研节奏——自研节奏=新指纹（F7 教训）。

### 2.2 诚实定位

熵检验可以区分"均匀随机流"与"真实网站流量分布"。逃生舱模式的定位是**特征匹配下不可识别**（不被精准封禁），不是统计下不可疑（可能被整段限速）——"活着比好看重要"。

## 3. 业界对照

|---|---|---|---|
| Hysteria2 | QUIC+密码认证+h3 伪装响应（masquerade 可反代真站）+可选 Salamander 混淆+Brutal 限速 | TLS 指纹依赖 quic-go+utls；固定速率整形本身可统计 | **"伪装默认+混淆逃生舱"双模式组合的完整先例**；认证失败不回错误码 |

## 4. 多路径的指纹问题

- **多五元组分发（RFC §7 原设计）= 最强流量特征**：同一逻辑流的分片同时出现在多条五元组且时间强同步，没有任何自然应用如此行事。维持 03 报告结论：**单 QUIC 连接多 stream 优先**。
- 单连接多 stream 的残余指纹：h3 本身就是多 stream 协议，内层聚合在形态上与"浏览器访问 HTTP/3 网站"同构——这是选 QUIC 内层聚合的先天优势；残余风险在 stream 生命周期模式（并发数、首包长度、开关顺序）与复用流量的包间自相关，需用真实业务流量对照测量，不靠猜。
- **把调度整形做成抗检测资产**（自研协议层真正加分的地方）：
  1. **按路径负载自动 padding**：聚合分片填充到离散档位（1K/4K/16K），切断"分片大小↔应用写入大小"映射。调度器知道每条路径的排队深度，可只在拥塞路径补 padding，让填充看起来像该路径自身的抖动而非统一策略；
  2. **跨路径去相关**（若确需多节点高级模式）：每条五元组独立 pacing + 50–200ms 随机相位，禁止同步突发；
  3. **调度器禁止合成探测流量**（F15：JSON 测速是教科书级签名），测速复用真实业务统计；
  4. **联动约束**：调度分片尺寸 × QUIC padding 档位 × obfs 长度不变性三者必须一起设计，避免叠加变形产生新规律。

## 5. 给架构师的约束清单

### 5.1 模式开关（协议层必须支持）

| 项 | 约束 |
|---|---|
| `mode` | `masquerade`（默认）/ `obfs`，互斥不叠加，连接建立前由配置确定 |
| obfs 密钥 | 独立于认证 PSK 的第二密码（防一处泄漏全暴露）；per-packet salt ≥8B；禁止静态 key |
| masquerade 必选项 | ALPN=h3、SNI 可配置、ACME 真证书或自签+SPKI pin、认证失败静默关流、h3 伪装响应（最小响应或反代真站） |
| 硬禁令 | 密文外任何 Magic/固定前缀/固定长度首包；固定周期心跳；JSON 协议；明文 PUNCH/STUN（F15 全部禁令） |
| 帧结构 | 多路聚合 chunk 头只存在于 QUIC stream 密文内，永不外露 |

### 5.2 性能红线（obfs 层）

- 每报文恰一次流密码运算（keystream XOR），无二次缓冲、无逐包堆分配（复用缓冲池）；
- 吞吐代价：AES-NI/AVX2 下 ChaCha20 ≈1.5–3 GB/s/核、AES-GCM ≈1–3+ GB/s/核，折算 1Gbps 满速单核占用 <15%，每包增量 <10μs、延迟增量 ≤0.1ms；
- padding 档位 ≤1500B（不得引发 IP 分片），不破坏 QUIC 初始包 1200B 约束；
- 去相关延迟只允许加在聚合备路径，主路径 0 附加延迟；
- 所有整形参数（抖动窗口、padding 档位）可配置，且每一项"看起来更随机"的参数都要有"为什么像正常流量"的理由，否则不加。
