# Hydra-Multipath-Proxy GUI 重设计方案 v2

> 产品设计 × 交互设计双角色 · 2026-10-04 · 仅设计，不含实现代码
> 解决老板批评：① 信息架构乱（对标 Clash Verge / v2rayN）② 证书出现在设置页的职责错位 ③ 节点编辑/订阅可见性/节点级凭据缺失

## 1. 竞品信息架构调研结论

### 1.1 Clash Verge Rev 页面清单（已查证）
| 页面 | 内容 |
|---|---|
| 主页 Home | 流量/连接速度图表、系统代理·TUN·服务模式快捷开关、核心信息、日志摘要卡片 |
| 代理 Proxies | 策略组 + 节点选择、延迟测试 |
| 订阅 Profiles | 订阅卡片列表（URL/更新时间/使用中标记）、导入/更新/删除 |
| 连接 Connections | 实时连接表（目标、规则、链路、上下行） |
| 规则 Rules | 分流规则只读列表 |
| 日志 Logs | 核心日志流、级别过滤 |
| 设置 Settings | 分区组：**系统设置**（语言/主题/开机自启/系统代理/托盘/窗口）、**Clash 核心**（端口、TUN 模式及 TUN 专属设置、DNS、模式）、**外观**（字体/布局）、**外部控制**（API）、**数据备份/版本** |

关键事实：**证书/密钥在 Clash Verge 中不出现在设置页**——订阅(P)、节点(P)自带 TLS/Reality 凭据，TUN 在设置页"Clash 核心"分组（服务模式入口旁）。

### 1.2 v2rayN 组织方式（已查证）
- 主界面 = 单列表（服务器列表）+ 顶部工具栏（订阅分组下拉、开关按钮）；右键"设为活动服务器"。
- **节点编辑对话框字段**：地址、端口、用户ID(UUID)、alterId(0)、加密方式、传输协议(tcp/ws/grpc/h2/kcp/quic)、TLS 开关 + SNI/伪装域名/path/host、备注、订阅分组归属。
- 订阅分组独立管理（订阅设置对话框），节点自动归入分组。

### 1.3 必须遵循的用户心智惯例（共性设计原则）
1. **主页=仪表盘+全局开关**（代理开关/TUN/系统代理），不是配置页。
2. **凭据跟着节点/订阅走**，设置页只放应用级配置——这就是"设置页出现证书=职责错位"的行业标准答案。
3. **节点是列表实体**：可增删改、测延迟、设活动节点、备注、按来源分组。
4. **订阅与节点分离呈现**：订阅管理订阅源；节点列表展示归属来源。
5. **TUN 是设置页里的一组开关**（主开关 + 依赖项），不是独立页面。
6. 日志/连接是**只读观测页**，无配置项。

## 2. Hydra 新信息架构（基于真实能力裁剪）

现有能力：多路径节点池、PSK 认证、节点证书（DER）、masquerade/obfs 传输模式、订阅(v1)、分享链接 v2+二维码、托盘、延迟测速、日志、配置持久化、`probe_interval`、本地监听地址。无连接表/规则引擎 → 不设"连接/规则"页。

**页面清单（5 页）**：状态总览 / 节点 / 订阅 / 日志 / 设置（+节点编辑对话框、分享对话框、订阅编辑对话框）。

### 2.1 状态总览（Dashboard）——一句话：运行状态与全局开关
```
┌────────────────────────────────────────────────┐
│  Hydra 代理   ● 运行中          [ 启动/停止 ]  │
│  本地监听 127.0.0.1:1080   活动: 3/5 节点在线  │
├────────────────────────────────────────────────┤
│ ┌──────────┐ ┌──────────┐ ┌──────────┐         │
│ │活动节点   │ │传输模式   │ │聚合吞吐   │(预留)  │
│ │node-a x3 │ │ obfs     │ │ --       │         │
│ └──────────┘ └──────────┘ └──────────┘         │
├────────────────────────────────────────────────┤
│ 最近日志（3 行摘要，点击跳日志页）              │
└────────────────────────────────────────────────┘
```

### 2.2 节点——一句话：所有节点的唯一权威列表（手动+订阅合并展示）
```
┌─────────────────────────────────────────────────────────┐
│ [手动添加 host:port…] [添加]      [测全部延迟] [分享选中]│
├─────────────────────────────────────────────────────────┤
│ ● node-a:443   [手动]   延迟 45ms   [活动] [编辑][分享][删]│
│ ○ node-b:443   [机场A]  延迟 120ms      [编辑][分享][删] │
│ ○ node-c:443   [机场A]  超时            [编辑][分享][删] │
└─────────────────────────────────────────────────────────┘
```
来源标记复用现有 `NODE_SOURCE_MANUAL`/订阅名；订阅节点默认只读（地址/凭据随订阅更新覆盖），可"另存为手动节点"后再改。

### 2.3 订阅——一句话：只管订阅源的生命周期（增/改/更新/删除），节点归属见 2.2
```
┌────────────────────────────────────────────────────┐
│ 订阅列表                                           │
│ ┌──────────────────────────────────────────────┐   │
│ │ 机场A   https://…/sub   更新于 2h前  [12 节点]│   │
│ │                       [立即更新][展开节点][编辑][删除]│
│ └──────────────────────────────────────────────┘   │
│ [ + 添加订阅（URL / 本地文件） ]                    │
└────────────────────────────────────────────────────┘
```
「展开节点」滚动定位/过滤 2.2 列表中该订阅的节点（复用 `SubscriptionConfig.nodes` 地址清单）。

### 2.4 日志——一句话：只读运行日志流（现状保留，加级别过滤与清空）。

### 2.5 设置——一句话：应用级配置，无任何凭据
```
┌────────────────────────────────────────────────┐
│ ◈ 代理核心                                     │
│   本地监听地址    [127.0.0.1:1080    ]         │
│   探测间隔(秒)    [30]                         │
│ ◈ TUN 模式（预留）                             │
│   [✓] 启用 TUN 模式  (禁用, tooltip:「规划中」)│
│ ◈ 系统                                         │
│   [✓] 开机自启    [✓] 关闭窗口最小化到托盘    │
│ ◈ 外观与数据                                   │
│   主题[深色(唯一)]  配置目录路径 [打开目录]     │
│ ◈ 关于  版本 / 检查更新(预留)                  │
└────────────────────────────────────────────────┘
```

## 3. 三个关键裁决

| # | 裁决 | 内容 |
|---|---|---|
| A | **证书/密钥归属** | 节点级。每节点自带 `auth_key / cert_path 或 cert_der / hydra_mode / obfs_key`，在节点编辑对话框内填写；分享链接导入时自动入库。**不设全局凭据库**（单用户客户端无需多节点共享一套凭据的抽象）。设置页中现有"安全与传输"组整体迁出。 |
| B | **订阅与节点关系** | 订阅=节点来源的管道（一对多）。订阅页只管源；节点页是唯一列表，用来源标记区分。订阅节点更新时整批替换（沿用现有 `SubscriptionConfig.nodes` 替换语义），凭据字段随订阅/分享链接下发。 |
| C | **设置页最终清单** | 代理核心（监听地址、探测间隔）/ TUN 预留开关 / 系统（自启、关窗到托盘）/ 外观与数据（主题、配置目录）/ 关于。**移除**：认证密钥、证书路径、传输模式、obfs 密码。 |

## 4. 节点编辑对话框字段定版（对标 v2rayN 节点编辑）

| 字段 | 控件 | 必填 | 当前是否实际生效 |
|---|---|---|---|
| 备注名 | 文本 | 否 | ✅（node_names） |
| 地址 host:port | 文本 | ✅ | ✅ |
| 认证密钥 PSK (hex) | 密码框+显示切换 | ✅ | ⚠️ 当前全局单值（GuiConfig.auth_key），未按节点生效 |
| 节点证书 | 文件路径 或 内嵌 DER(b64)，二选一 | ✅ | ⚠️ 当前全局单值（cert_path/cert_der_b64） |
| 传输模式 | 下拉：masquerade/obfs | ✅ | ⚠️ 当前全局单值（hydra_mode） |
| obfs 密码 | 密码框（仅 obfs 时显示） | 条件 | ⚠️ 当前全局单值（obfs_key） |
| 来源 | 只读标签 | — | ✅（手动/订阅名） |

对话框底部提示条：「当前 hydra-client 按全局凭据连接，节点级凭据将在后端改造后逐节点生效」——诚实呈现，见 §5。

## 5. TUN 模式预留设计

- **是什么**：虚拟网卡全流量接管（Windows 依赖 wintun.dll + 服务模式/管理员权限），比系统代理覆盖面广（终端/CLI）。
- **UI 占位规范**：设置页 TUN 分组，`Switch` 控件 `enabled=false`，默认值 off，tooltip「TUN 模式规划中，当前请使用本地代理 127.0.0.1:1080」；分组下预留「服务模式安装」「TUN 栈(gVisor/System)」两项灰色占位。持久化字段 `tun_enabled: bool = false` 预留但不驱动任何行为。
- **后端工作量级**（不实现）：wintun 集成+管理员提权/服务：**大（4~6 周）**；虚拟网卡路由/DNS 配置：**大（3~4 周）**；与多路径池对接、回归：**中（1~2 周）**。合计 ≥2 个月，建议独立立项。

## 6. UI 目标态 vs 当前生效对照表（hydra-client 改造输入）

| 字段 | UI 目标态（节点级） | 当前生效（全局） | 改造点 |
|---|---|---|---|
| node_addrs | 节点对象数组 | Vec<String> | 池按节点建连 |
| auth_key | 每节点 | GuiConfig.auth_key 单值→env | pool.rs 握手逐节点携带 |
| cert | 每节点 | 全局 resolve_node_certs 一次 | transport.rs 逐节点加载 |
| hydra_mode | 每节点 | 全局 env | transport.rs 按节点选择 |
| obfs_key | 每节点 | 全局 env | 同上 |
| 备注/来源/延迟 | 每节点 | 已生效 | 无 |
| 监听地址/探测间隔/托盘/自启 | 全局 | 已生效 | 无 |

## 7. 实施计划

| 阶段 | 内容 | 验收标准 | 工作量 |
|---|---|---|---|
| P1 IA 重排 | 5 页导航、设置页瘦身（凭据迁出→临时放"节点页顶部全局凭据"过渡区）、总览页仪表盘、订阅页独立 | 老板批评①②闭环；设置页无任何凭据字段；全部功能可达 | 3~4 天 |
| P2 组件规范 | 节点编辑对话框（§4 字段）、订阅编辑/更新流程、分享对话框整合、TUN 占位、控件/间距/图标规范表 | 对话框字段与 §4 一致；TUN 开关 disabled+tooltip；深色对比度回归通过 | 4~5 天 |
| P3 凭据模型后端 | hydra-client 节点级凭据（§6 表）、GUI 数据结构 Node{...} 迁移、旧配置自动迁移 | 节点各带不同证书/模式可同时连接；旧 config.json 无损升级 | 2~3 周（含客户端改造） |

风险：P3 触及 hydra-client（WS-A/WS-B 所有）的 env 接口，需跨组评审；P1/P2 可独立先行。
