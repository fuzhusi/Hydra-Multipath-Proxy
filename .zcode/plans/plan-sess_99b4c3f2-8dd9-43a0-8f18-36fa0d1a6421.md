## 二、抽取边界（已按代码实况核实）
- **搬入 hydra-core**：12 个平台无关模块 + `auth_key_from_hex`/`node_certs_from_paths`/`DEFAULT_SNI`。
- **留 hydra-client（桌面）**：`main.rs`、`tun.rs`、`auth_key_from_env`/`node_certs_from_env`/`node_certs_from_paths 的 env 版`、`tun_config_from_settings`、`hide_console_window`、`windows_system_proxy_enabled`、`ShutdownToken`/`new_tun_shutdown_token`。
- **兼容策略**：hydra-client `pub use hydra_core::…` 全量 re-export，GUI 与 CLI 代码零改动；`proxy.rs:283` 的 `#[cfg(feature="tun")]` 耦合点保持原门控（hydra-core 无 tun feature 时自然编译掉）。
- 依赖：workspace `Cargo.toml` 增 `hydra-core`、`hydra-android` 两个 member；rustls/ring/tokio 等继续走 workspace.dependencies（ring 单栈，已规避 aws-lc 交叉编译坑）。

## 三、uniffi 接口设计（v2.1 R4/R8 落地）
```rust
// 显式参数化，无 env：
interface HydraEngine {
    constructor(nodes: List<NodeSpec>, auth_key_hex: String, cert_der: List<Bytes>, trust: TrustMode)
    fun start(protect: SocketProtect)   // R4：出站 socket 保护回调
    fun stop()
    fun stats(): TrafficStats
}
callback interface SocketProtect { fun protect(fd: i32) }   // Kotlin 调 VpnService.protect；iOS 空实现
record NodeSpec(addr: String, sni: String?)
```
拆分时保持每个模块原样 git mv（保历史），hydra-core 内部引用 `crate::` 路径不变。
