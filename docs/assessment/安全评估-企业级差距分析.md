# 安全评估：企业级差距分析（2026-10-08）

> 评估基准：OWASP Application Security Verification Standard (ASVS) 4.0 L2 +
> CIS Software Supply Chain Security Guide + 企业 Rust 项目安全实践。
> 坦率声明：本项目定位为个人代理工具，"企业级"意味着安全意识强的组织可以
> 直接部署而无需额外加固。以下按"达标 / 有差距 / 缺失"三级如实评级。

---

## 总评：传输层安全 ✅ 达标 · 运营层安全 ❌ 有显著差距

**结论：加密与协议安全已达企业标准，但供应链安全、流程门禁、可观测性三个维度存在结构性缺失。**

---

## 1. 传输安全 ✅ 达标

| 控制项 | 实现 | 评级 |
|---|---|---|
| 传输加密 | TLS 1.3（禁 1.2 降级）+ ChaCha20-Poly1305 | ✅ |
| 前向安全 | Noise_NNpsk2_25519（每次握手新鲜临时密钥） | ✅ |
| 证书验证 | 自签 pinning / ACME CA + 可选叶 SHA-256 硬 pin | ✅ |
| 中间人防护 | confirm 绑定 = 叶证书 SHA-256 + TLS exporter（双通道） | ✅ |
| 协议指纹 | 无 ALPN / 禁会话恢复 / Chrome 近似 ClientHello | ✅ |
| 反重放 | 握手哈希唯一性（新鲜临时 e → 重放即失败） | ✅ |
| 通道绑定 | confirm 含 TLS exporter（跨连接转发/重放即失效） | ✅ |

## 2. 访问控制 ⚠️ 有差距

| 控制项 | 实现 | 评级 | 差距 |
|---|---|---|---|

| SSRF 防护 | 全段位黑名单 + 内嵌 v4 复查 | ✅ | — |
| 连接限额 | Semaphore 1000 + per-IP 256 + idle 300s | ✅ | — |

## 性能评估

### 当前瓶颈：每请求新建连接

```text
当前模型（每请求）：
浏览器 → [TCP握手 1RTT + TLS1.3 1RTT + Noise 1RTT] → 节点 → 目标
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
         每次请求都要做：约 2-3 RTT 到节点 = 100-500ms 额外延迟
```

### 改进方案：连接池（预建连接复用）

```text
改进后（连接池）：
启动时/预热 → [建 N 条到节点的已认证连接] → 池化
请求 → 从池中取空闲连接 → 直接转发（0 额外握手延迟）
连接用完 → 归还池（或空闲超时后销毁）
```

| 指标 | 当前 | 连接池后 |
|---|---|---|
| 首请求延迟 | ~500ms（握手） | ~500ms（池预热） |
| 后续请求延迟 | ~500ms（每次握手） | ~0ms（复用） |
| 安全性 | 每请求独立密钥 | 池连接共享密钥（但 TLS 1.3 内建 key update） |
| 复杂度 | 低 | 中（池管理/超时/并发） |

**评估结论**：连接池是最大的性能提升点（后续请求延迟从 ~500ms 降到 ~0ms），
但改动面大（tcp_transport + proxy + 超时/并发/清理），不适合与安全加固混合
做。建议单独一批执行。
