## 0. 执行总则

1. **文件所有权制**：每个 WS 独立文件清单，越界即违规（清单见各 WS，含 Cargo.toml 归属）
2. **回滚验收**：每个任务一个独立 commit，回滚单位=任务；每波次总控回归（17/17+E2E）通过才合入
3. 硬门槛：`cargo test -p hydra-client -p hydra-node -p hydra-protocol` 全绿 + 各 WS 验收测试
4. 全程不推送 GitHub；每波次总控做 E2E 并提交一次
5. 宁缺勿假：验收达不成如实标注降级/推迟，不伪造完成
6. 评审已修正的技术事实（执行时不得沿用报告 v1.0 的错误写法）：
   - quinn 0.10 无 `SendStream::stop`；正确 API = `SendStream::reset(VarInt)`（RESET_STREAM，对端读到 `ReadError::Reset`）+ `RecvStream::stop(VarInt)`（STOP_SENDING，对端 write 得 `WriteError::Stopped`）
   - 节点侧"静默 drop send"实为优雅 FIN——客户端读到干净 EOF 冒充正常结束；A3 的实质 = **EOF→可区分错误码**
   - 应用错误码 0x11-0x13 合法（RFC 9000 §20.2 应用码无约束；0x00-0x3f 保留仅针对传输层码）
   - 连接级接收窗口 quinn 默认 `VarInt::MAX`（无上限）；调 32MB 是内存封顶，不是吞吐提升；吞吐杠杆只有 `stream_receive_window`（默认 1.25MB≈150ms RTT 下 66Mbps）
