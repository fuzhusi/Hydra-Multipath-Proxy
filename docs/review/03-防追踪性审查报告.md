# Hydra Multipath Proxy 防追踪性（抗探测/抗指纹）审查报告

- 审查对象：`D:\Project\Hydra-Multipath-Proxy`，代码版本 `e78c927`（feat: 实现智能 DNS 解析方案）
- 审查视角：网络中间设备（ISP/DPI/GFW 类审查系统）能否**识别、指纹化、追踪、精准封锁**该代理流量

## 0. 结论摘要

**一句话结论：当前实现是一个"不设防的 QUIC"——一个被动 DPI 只需解密 QUIC Initial 包（密钥公开可算）读出 `ALPN=hydra` + `SNI=localhost` 即可 100% 识别；一个主动探测者甚至无需任何密钥，直接连上去就能拿到自签 localhost 证书并把节点当开放中继使用，识别成本约等于一次 UDP 探测。** 唯一的"好消息"是 README 宣称的带 Magic 的自定义二进制协议实际是死代码，线上传输的是"裸 TCP over QUIC"，避免了 Magic 字段这类最低级协议指纹。

| 维度 | 评级 | 说明 |
|---|---|---|
| 传输层指纹（TLS/QUIC ClientHello） | ★★★★☆ 高危 | ALPN/SNI 直接暴露工具名；rustls 栈指纹与浏览器差异巨大 |
| 协议层指纹（应用层协议结构） | ★★★★☆ 高危 | 服务端无认证、两字节应答码可被主动探测一轮回合识别；客户端跳过证书校验使链路上任何人可 MITM 后明文识别 |
| 流量层指纹（包长/时序/方向） | ★★☆☆☆ 中危 | 无填充无整形，10 秒周期 keepalive 心跳是稳定 beacon；多路径聚合当前未上线（上线后将成最强特征） |
| 行为侧信道（DNS/STUN/链接/配置） | ★★★☆☆ 中危 | DNS 回退路径裸 UDP 53 泄漏目标域名；硬编码公共节点 IP；`hydra://` 链接格式独特 |

## 1. 威胁场景定义：DPI 在每一层能看到什么

### 1.1 L3/L4（完全明文）
- 五元组：客户端 IP:随机端口 → 节点 IP:**UDP 8080**（`hydra-node/src/config.rs:15`、`hydra-node/src/server.rs:23`）
- 协议类型：UDP。非 443 端口上跑 QUIC（长头部 `0b11xxxxxx` 版本 0x00000001）本身就是一个轻量筛选条件。

### 1.2 QUIC Initial 包（**密钥公开，人人可解密**）
QUIC v1 的 Initial 包加密密钥由首包中的 Destination Connection ID 派生（RFC 9001），DPI 无需任何先验知识即可解密并读出完整 ClientHello。以下字段**全部明文可见**：
- **SNI = "localhost"**（`hydra-client/src/transport.rs:68`、`hydra-client/src/pool.rs:173` 硬编码 `connect(addr, "localhost")`）
- **ALPN = "hydra"**（客户端 `transport.rs:28`，服务端 `hydra-node/src/server.rs:37`）
- 密码套件与扩展序列：rustls 0.21.12 + quinn 0.10.2 固定输出（Cargo.lock 锁定），无 GREASE、无证书压缩、无后量子群、扩展顺序固定 → 稳定的 JA3/JA4 式哈希
- QUIC 传输参数（quinn 默认值组合）
- 会话恢复 ticket 身份（rustls 默认开启内存会话缓存，同一客户端进程的所有连接复用同一 ticket → 跨连接关联标识）

### 1.3 握手之后（被动不可解密）
TLS 1.3 + QUIC 保护生效后，被动观察者只能看到：包长序列、包间时序、方向比、双向流（stream）数量、连接生命周期、keepalive 节奏。无任何填充/整形时，包长直接映射被代理 HTTPS 流量的大小。

### 1.4 主动探测（审查者主动发流量）
- **服务端对任何人不做认证**（`hydra-node/src/handler.rs:21-58` 全文无鉴权；`hydra-protocol/src/auth.rs` 的 HMAC/PBKDF2 是死代码）→ 探测者可完成握手、打开流、发送 `host:port` 字符串，通过 **2 字节应答码**（0x00/0x01/0x02，`handler.rs:78/88/107/115/123`）和"节点真的会替我连出去"的行为一轮回合确认身份，还可白嫖开放中继。
- 证书：`rcgen::generate_simple_self_signed(vec!["localhost"])`（`server.rs:28`），每次启动重新生成、CN=localhost、非公共 CA。
- **客户端 `SkipVerification` 接受任意证书**（`transport.rs:25,108-122`）→ 链路上的审查设备可透明 MITM：替客户端完成握手 → 读出明文目标地址（内层协议是 ASCII `host:port`）→ 确凿识别 + 获取用户访问目标。

### 1.5 端点/带外侧信道
- DNS：服务端解析失败（应答 0x02）时客户端回退到 `tokio::net::lookup_host`（`hydra-client/src/proxy.rs:476`）→ 系统 resolver → **裸 UDP 53 明文查询目标域名**，ISP 可直接记录访问历史，且该查询与紧随其后的 QUIC 流在时间上强关联。
- STUN：硬编码 Google 公共 STUN 服务器（`nat_traversal.rs:7-11`）——当前为死代码，若启用则 UDP 19302 明文 STUN 直接暴露"在用穿透工具"。
- 分享链接 `hydra://ip:port?...`（`share_link.rs:69-72`）：全网独有 scheme，无任何凭据字段（侧面印证节点无鉴权）。
- 硬编码默认节点公网 IP `43.130.251.236:8080`（`hydra-client/src/main.rs:19` + README）→ 按名单一键封禁/DoS。
- 系统代理痕迹：GUI 写 GNOME gsettings / 环境变量（`hydra-client-gui/src/main.rs:374-410`），与 v2rayN 同款，端点本地痕迹，网络不可见，风险低。

## 2. 指纹特征清单

分级：【可识别度 高】= 单特征即可确定判型；【中】= 需组合或统计；【低】= 弱信号。

### F1. ALPN = "hydra"（非标 ALPN）
- **【可识别度 高】** `hydra-client/src/transport.rs:28`、`hydra-node/src/server.rs:37`
- 特征：QUIC Initial 可被 DPI 公开解密，ClientHello 的 ALPN 扩展明文列出 `hydra`。全网只有本工具使用该 ALPN。
- DPI 利用：一条规则 `udp && quic_initial_decrypt(alpn=="hydra") → block/log` 即完成对客户端与服务端的**全量精准识别**，误报率为零。
- 缓解：改用 `h3` ALPN 并让服务端对未认证探测表现出 HTTP/3 站点行为（Hysteria2 路线）；注意任何自定义 ALPN 在 QUIC Initial 中永远可见，ALPN 本身无法加密。

### F2. SNI = "localhost"
- **【可识别度 高】** `hydra-client/src/transport.rs:68`、`hydra-client/src/pool.rs:173`
- 特征：真实浏览器/CDN 流量绝不会出现 SNI=localhost 的 QUIC ClientHello。
- DPI 利用：`sni=="localhost" && udp` 单条规则即可；且 SNI 与 ALPN 交叉验证。
- 缓解：SNI 填写节点真实域名；进一步走"借用高权重站点域名"（见路线图）。

### F3. 自签 CN=localhost 证书 + 每次启动重生成
- **【可识别度 高（主动探测）】** `hydra-node/src/server.rs:28`
- 特征：任何探测者完成握手即可读取证书：CN=localhost、非公共 CA 签发、每次重启指纹变化。
- DPI 利用：扫描器批量握手收证书，自签 localhost = 代理服务实锤（浏览器正常站点不可能自签 localhost）。
- 缓解：Let's Encrypt 真证书（HTTP-01/DNS-01），客户端用 SPKI 指纹锁定（放进分享链接），删除 SkipVerification。

### F4. 客户端跳过全部证书校验（SkipVerification）
- **【可识别度 高（使 MITM 识别成为可能）】** `hydra-client/src/transport.rs:25,108-122`
- 特征：这不是网络可见特征，但它使**链路上任何中间设备都能冒充节点**，进而读取内层明文协议（F6）并确认工具身份。同时密钥交换形同虚设（任意人可中间人）。
- DPI 利用：审查设备在线路侧主动 MITM 探测，一跳定案。
- 缓解：与 F3 一并修复——真证书 + 指纹锁定；至少自签也要做 PSK/证书哈希校验（Hysteria2 的 TLS 指纹校验思路）。

### F5. 服务端零认证 + 开放中继行为
- **【可识别度 高（主动探测）】** `hydra-node/src/handler.rs:21-58`（无鉴权调用）；`hydra-protocol/src/auth.rs` 整文件死代码
- 特征：任何匿名连接可打开流并让节点向外发起任意 TCP 连接。README 宣称的 HMAC 认证未接入处理链路。
- DPI 利用：① 探测确认身份；② 无认证开放中继会被审查系统列为"候选代理→封锁"，也会被第三方扫描滥用导致节点 IP 进入黑名单。
- 缓解：接入 HMAC Token（auth.rs 已有实现，工作量小）；对认证失败**不回显可区分错误**——直接关闭或静默丢弃，避免错误码侧信道。

### F6. 内层协议：ASCII "host:port" + 2 字节状态码（0x00/0x01/0x02）
- **【可识别度 中（被动不可见；对 MITM/节点侧/主动探测为确定性签名）】** 客户端发送 `hydra-client/src/proxy.rs:249,378,685`；服务端解析 `hydra-node/src/handler.rs:53-58`；应答码 `handler.rs:78,88,107,115,123`
- 特征：首个 stream 字节是 `域名:端口` 的 ASCII 文本，随后 2 字节应答。任何能读到 stream 明文的一方（MITM、节点、拿到 node 权限的审查者）可据此 100% 判型。DNS 重试机制（0x02→客户端重发 IP，`proxy.rs:467-522`）进一步形成独特的两段式时序。
- DPI 利用：配合 F4 的 MITM，即"解密即判型"。
- 缓解：协议本身没问题（藏在 TLS 里），关键是修复 F3/F4 让"读"变得不可能；若追求深度抗探测，可对首包做长度归一化填充。

### F7. 10 秒周期 keepalive + 60 秒 idle timeout
- **【可识别度 中（被动统计）】** `hydra-client/src/transport.rs:34-35`、`hydra-node/src/server.rs:43-44`（双侧 10s keepalive）
- 特征：空闲连接上每整 10 秒一个固定小包（PING 帧），持续整点、无抖动。浏览器 QUIC 连接不保持这样规整的心跳。
- DPI 利用："长寿命 UDP 流 + 严格 10s 周期微包"是经典 beacon 检测模型，可筛出代理长连接。
- 缓解：去掉固定 keepalive 或改为 30–120s 随机抖动；idle timeout 放宽。

### F8. rustls/quinn 客户端 TLS 指纹（无 GREASE、固定套件序、无 PQ 群）
- **【可识别度 中（被动，需组合规则）】** 依赖版本：`Cargo.lock` quinn 0.10.2 / rustls 0.21.12 / ring 0.16；ClientHello 构造 `transport.rs:23-30`
- 特征：与 Chrome（GREASE、X25519+Kyber、证书压缩、ALPS、扩展乱序）差距极大；rustls 0.21 输出固定的 cipher 列表（0x1302,0x1301,0x1303 顺序）、无 GREASE、仅 TLS1.3、固定扩展集 → JA3/JA4 哈希全网唯一且随 quinn 版本集体升级时批量切换。
- DPI 利用：对"非浏览器 QUIC 指纹 + 非标准端口"做概率封禁；也可用 QUIC 指纹白名单机制（只放行 Chrome/Firefox 指纹的 QUIC）一刀切。
- 缓解：见路线图中期项——Rust 生态现状是**没有生产级 uTLS 等价物**（Go 的 refraction-networking/utls + quic-go 是 Hysteria2/sing-box 抗指纹的根基）。可做的：减少自证特征（F1/F2/F3）优先；真正模拟浏览器 Hello 需要自己扩展 rustls（工作量很大）或换栈。

### F9. QUIC 跑在 UDP 8080 而非 443
- **【可识别度 低-中】** `hydra-node/src/config.rs:15`
- 特征：非 443 UDP 上的长寿命 QUIC。
- DPI 利用：弱筛选条件，与其他特征组合使用。
- 缓解：改 443/UDP；服务端可同端口跑真 HTTP/3 站点做掩护（中期）。

### F10. 会话恢复 ticket 身份跨连接关联
- **【可识别度 低-中（被动关联）】** rustls 0.21 默认 `in_memory_sessions`；ClientConfig 全池共享（`transport.rs:19-41`，`pool.rs` 复用同一配置）
- 特征：同一客户端进程发起的多条 QUIC 连接，其 ClientHello 中携带同一 NewSessionTicket 身份（该字段在 Initial 中被动可见），可跨连接、跨本地端口关联同一用户。
- DPI 利用：把"同一用户的多次会话"串联成行为画像（追踪性核心诉求）。
- 缓解：禁用会话恢复（`Resumption::disabled()`，一行）或定期清空缓存；牺牲少量握手延迟。

### F11. 启动期连接池预热突发
- **【可识别度 低】** `hydra-client/src/proxy.rs:63-66`（每节点瞬时 2 条 QUIC 握手）
- 特征：进程启动瞬间对节点地址的密集握手。
- DPI 利用：与 GUI 启动行为关联做端点画像；弱信号。
- 缓解：预热随机延迟打散（几行代码）。

### F12. DNS 回退路径泄漏目标域名（行为侧信道，近期提交核心）
- **【可识别度 高（对"追踪访问记录"这一目标）】** `hydra-client/src/proxy.rs:476`（`tokio::net::lookup_host` → 系统 resolver → 裸 UDP 53）
- 特征：仅当服务端 DNS 失败回错误码 0x02 时触发，但触发时目标域名**明文出现在运营商网络**，且与该时刻的 QUIC 流时间关联；e78c927 之前的历史版本（0354038）曾全程本地解析，泄漏面更大，当前 HEAD 只剩回退路径。
- DPI 利用：无需解密 QUIC，只监听 UDP 53 即可记录用户访问目标 + 定位"该用户在用某代理"（53 查询与 QUIC 流同秒出现）。
- 缓解：回退改为"经节点代为解析"（新增协议命令）或客户端 DoH（bootstrap 用 IP）；绝不静默回退到 53。

### F13. 硬编码公共节点 IP + README 公开
- **【可识别度 高（对该特定节点）】** `hydra-client/src/main.rs:19`、README 两处
- 特征：`43.130.251.236:8080` 公开在仓库中。
- DPI 利用：名单封禁/端口封锁/DoS，零成本。
- 缓解：移出代码与文档，走配置/订阅。

### F14. `hydra://` 分享链接格式
- **【可识别度 低（带外）】** `hydra-client/src/share_link.rs:69-72`
- 特征：全网独有 scheme；且链接内**无任何凭据**（印证 F5），任何人拿到即可直连。
- DPI 利用：聊天/网页中出现的 `hydra://` 是用户身份线索（类似老版 ss:// 被扫描）。
- 缓解：链接中加入 PSK/证书指纹字段；必要时对外观做通用化（如 `https://...#base64` 订阅格式）。

### F15. 死代码群：Magic 协议 / HYDRA_PUNCH / STUN 列表 / JSON 测速
- **【当前风险：无（未上线）；启用后风险：高】**
  - `hydra-protocol/src/packet.rs:21`：Magic = `0x48594452`（"HYDR"）固定首字段——一旦 Splitter 路径启用，首个 QUIC stream 前若干字节结构固定（magic+session_id+stream_id+chunk_id+offset+length），DPI 在拿到明文（或配合 F4 MITM）后一条特征码即可判型；CRC32 校验无密码学意义。
  - `hydra-client/src/speedtest.rs:82-97`：把 Packet 用 **serde_json 序列化**发送，payload 是字面量 `"speedtest"`——字段名 JSON 结构是教科书级签名。
  - `hydra-client/src/nat_traversal.rs:287-300`：明文 `b"HYDRA_PUNCH"` UDP 打洞包；`:7-11` 硬编码 Google STUN 服务器。
  - 说明：经 grep 确认，`Splitter`/`Assembler`/`Crypto`/`speedtest`/`nat_traversal` 均未被 `proxy.rs`/`main.rs`/GUI 调用——**当前线上数据路径 = 裸 TCP over 单条 QUIC stream，无多路径分发**。RFC §7 的"一个逻辑连接拆多节点"若按现设计上线，同一逻辑流同时出现在多条五元组上且时间强同步，将成为比 Magic 更强的流量层特征，需在设计阶段解决。

## 3. 与主流工具抗检测能力对比

| 能力 | Hydra（当前） | Xray VLESS+REALITY | Hysteria2 | TUIC | Trojan |
|---|---|---|---|---|---|
| 传输层伪装（ALPN） | ❌ 自定义 `hydra`，一眼假 | ✅ TLS over TCP，无 ALPN 泄漏问题（TCP 侧不暴露 ALPN 于公开密钥） | ✅ ALPN=h3，与真实 HTTP/3 无法区分 | ⚠️ 自定义 ALPN（可配置，同样可见） | n/a（TCP TLS） |
| SNI/证书 | ❌ localhost 自签 + 客户端不校验 | ✅ 借用真实站点证书（STEAL）、SNI 指向高权重站、探测者看到真站 | ✅ 真证书（ACME）或自签+pin | ⚠️ 自签+pin 或真证书 | ✅ 真证书（仿站） |
| 认证与抗探测 | ❌ 无认证，握手必成功，错误码可区分 | ✅ 无 REALITY 键的探测被导流到真站 | ✅ 密码认证，失败可伪装成正常 h3 响应/404 | ⚠️ 有认证，失败即断 | ✅ 密码，失败降级为静态站 |
| 被动流量指纹 | ⚠️ 10s 整周期心跳；无填充 | ⚠️ 无内建填充（可配 padding） | ✅ 内建 padding + Salamander 混淆 + Brutal 限速整形 | ⚠️ 一般 | ⚠️ 一般 |
| 客户端 TLS 指纹模拟 | ❌ 裸 rustls | ✅ uTLS 指纹池（chrome/firefox/ios…） | ✅ 基于 quic-go+utls | ⚠️ rustls 栈（同 Hydra 弱点） | ⚠️ Go TLS 栈 |
| 主动探测后果 | 节点被确认 + 被白嫖开放中继 | 探测者以为访问了真站 | 探测者以为访问了普通站点/404 | 连接被拒 | 看到伪装站 |
| DNS 侧信道 | ⚠️ 默认服务端解析（好），回退裸 53（坏） | ✅ 可全远端解析 | ✅ 远端解析 | ✅ 远端解析 | ✅ 远端解析 |

结论：Hydra 目前处在"最低配 TUIC"以下水平——比裸 Shadowsocks 多一层 QUIC 加密的偶然好处，但缺少所有成熟方案共有的三件套：**真证书/证书校验、认证、探测伪装响应**。

## 4. 防追踪改进路线图（按性价比排序）

### 短期（1–3 天，性价比极高）
1. **接通认证**：在 `handler.rs` 首包校验 HMAC Token（auth.rs 已写好，只差调用）；认证失败统一"静默关流"，不发 0x01/0x02 可区分错误码。工作量：小。
2. **杀掉回退 DNS 泄漏**：0x02 回退改为经节点代解析（新命令字）或客户端 DoH（IP 直连 bootstrap），删除 `proxy.rs:476` 的裸 53 路径。工作量：小。
3. **ALPN 改 `h3`**（客户端/服务端两侧，各一行）；SNI 改为节点真实域名（配置化，删除硬编码 "localhost"）。工作量：极小。
4. **真证书 + 客户端校验**：节点用 ACME 签发证书；分享链接加入证书 SPKI SHA-256 指纹；删除 `SkipVerification`，实现 SPKI pin verifier。工作量：中（脚本 + verifier 实现）。
5. **监听 443/UDP**；移除代码与 README 中的硬编码节点 IP。工作量：极小。
6. **去周期心跳**：keepalive 改 30–120s 随机抖动或关闭；预热连接随机延迟。工作量：极小。
7. **禁用会话恢复**（rustls `Resumption::disabled()`）阻断 ticket 关联。工作量：极小。

### 中期（1–3 周）
8. **探测伪装**：认证失败/未知协议的连接，服务端降级为一个最小 HTTP/3 响应（或反向代理到本机真实网站），对齐 Hysteria2 masquerade。工作量：中-大（涉及 h3 帧实现或集成 h3 crate）。
9. **流量填充/整形**：对 stream 首包与短控制包做随机填充，弱化包长↔内容映射；评估 Hysteria2 式整流（固定速率/加抖动）。工作量：中。
10. **重设计多路径聚合形态（关键取舍）**：若启用 RFC §7 的分片多发，改为"**单 QUIC 连接多 stream 聚合**"（同一五元组内复用，规避多条五元组同步抖动这一最强特征）优先于"多节点多连接"；确需多节点时引入去相关延迟与独立 pacing。工作量：大。
11. **清理死代码**：删除或将 `packet.rs` Magic 协议、`speedtest.rs` JSON 测速、`nat_traversal.rs` 明文 PUNCH 移入"未启用"特性门，防止未来无意上线带指纹路径；文档与实现对齐（README 的"自定义二进制协议+Magic"当前不成立）。工作量：小。
12. **rustls 指纹改善调研**：评估 rustls 扩展 GREASE/乱序的可行补丁、跟踪 rustls 混合后量子密钥交换进展；明确结论"Rust 生态暂无 uTLS"，把它记为架构级约束。工作量：调研小、实现大。

### 长期（1–2 月）
13. **REALITY 式证书借用/站点前置**：SNI 指向高权重真实站点、握手失败导流真站，使主动探测返回与真站一致的内容。工作量：大（需自研或移植握手分流逻辑）。
14. **浏览器级 ClientHello 模拟**：基于自定义 rustls provider 或换 QUIC 栈（如 quiche/boringssl 路线）实现 Chrome 同构 Hello；若目标是"对抗 QUIC 指纹白名单"，这是终点方案。工作量：很大。
15. **行为面收敛**：测速改为复用真实业务流量统计而非合成包；GUI 系统代理写入行为与主流工具对齐（低优先级，端点本地）。
