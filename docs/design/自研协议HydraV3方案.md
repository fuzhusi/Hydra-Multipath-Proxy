# 自研协议 Hydra V3 统一方案（设计委员会决策稿）

- 日期：2026-10-03 ｜ 撰写：首席架构师（委员会裁决稿） ｜ 输入：三位委员草案（文末 §8）＋ 审查总览 ＋ README
- 效力：与三份委员草案冲突之处以本稿为准；本稿只做决策，不改任何源码。

## 1. 一句话决策

我们要的"自己的东西" = **QUIC 密文之内的协议语义：Hydra 握手 v2（前向安全＋通道绑定）＋ 会话层多路径聚合与调度算法 ＋ 一套可选的线缆混淆基础设施——不是线缆格式。** 线缆上我们永远是"普通 h3 站点"（默认）或"均匀随机字节流"（逃生舱）；密码学只许组合标准件（snow/ring/HKDF），允许自研的仅限帧格式、握手流程、状态机、调度算法与混淆基础设施（01 §0 边界与 03 禁令合并生效）。

## 2. 分层架构（定版）

```
     masquerade 模式（默认）                   obfs 模式（逃生舱，显式开启）
     线缆形态 = 标准 h3 站点                   线缆形态 = 均匀随机字节
┌──────────────────────────────────────────────────────────────────┐
│ SOCKS5 / HTTP 代理入口（仅本地 127.0.0.1）                          │ L5
├──────────────────────────────────────────────────────────────────┤
│ 会话层：多路径聚合 / 调度 / 分片重组（V3.3）                         │ L4 ← chunk 帧只存在于
│       padding / 去相关整形也在本层                                  │    QUIC stream 密文内
├──────────────────────────────────────────────────────────────────┤
│ Hydra 握手 v2 ＋ 业务流（V3.2，QUIC 双向流内，                      │ L3 ← 连接后第一条流；
│       首字节版本判别 0x03=v3 / 0x00=v2）                           │    无独立"握手层"
├──────────────────────────────────────────────────────────────────┤
│ QUIC ＋ TLS 1.3（quinn＋rustls：ALPN=h3、SPKI pinning、             │ L2 ← masquerade 的
│       stateless retry、TLS exporter 通道绑定）                     │    完整伪装形态
├──────────────────────────────────────────────────────────────────┤
│ hydra-wrap 混淆层（可选）：每 UDP 报文 ChaCha20 keystream XOR       │ L1 ← obfs 时包裹以下
│       （AsyncUdpSocket 抽象；垃圾包静默丢弃＋每源令牌桶）             │    全部，含握手流
├──────────────────────────────────────────────────────────────────┤
│ UDP（推荐 443）                                                    │ L0
└──────────────────────────────────────────────────────────────────┘
```

- 两模式互斥不叠加，连接建立前由配置/分享链接确定（03 §1.2）：`mode=masquerade`（默认）｜ `mode=obfs`。
- obfs 开启时 QUIC 全部报文（含握手流）整体变为随机字节——握手天然在混淆密文之下，无需也不允许另设握手层。
- masquerade 必选项（03 §5.1，Phase A 已大半落地）：ALPN=h3、UDP 443、SPKI pin、认证失败静默、h3 伪装响应。

## 3. 裁决记录（三大分歧）

**分歧 1｜V3.1 是"混淆层当最快线缆身份"还是"先把 masquerade 做扎实"？**
→ 裁决：V3.1 = **双模式传输基础设施，masquerade 为默认线缆身份**。阶段内顺序：先 masquerade 收尾（h3 伪装响应等，约 2 人日——Phase A 已完成 ALPN/SNI/443/pinning/静默关流），再建 obfs 基础设施（5–8 人日，默认关闭）。理由：分析师成立——白名单审查下随机字节流是"不明加密 UDP"靶子，不配当默认；但重度审查地区白名单里本没有我们的位置，obfs 是唯一活路，且它便宜、独立可回滚（R3），先入库不亏。

**分歧 2｜ring 0.17 / rustls 0.23 升级进 V3 序列还是 Phase B？**
→ 裁决：**留在 Phase B（第 6 项），并作为 V3.2 的硬前置门**。V3.1 不依赖它（AsyncUdpSocket 与 rustls 版本不相交，可并行推进）；V3.2 的 exporter 通道绑定与 ring 0.17 原语是硬依赖，升级未落地不得开工 V3.2。理由：密码学草案自身禁止 ring 双版本并存，收敛为一次升级；也避免 V3 序列再背依赖回归风险。

**分歧 3｜握手 v2 放 QUIC 流内还是混淆层之下？**
→ 裁决：**握手 v2 永远在 QUIC 双向流内**（密码学评审立场），不存在"混淆层之下的独立握手"。obfs 开启时握手自然被包进随机字节（见 §2），已满足"握手在密文中"；把握手下放到裸 UDP 层等于自造传输层握手机（重传/反放大），违反红线，且丢失 TLS exporter 通道绑定，P0-2 的 MITM 转发修复即失效。

**附注（01/03 技术冲突裁定）**：obfs 报文变换定版为 03 草案的 `[12B salt][XOR keystream]`（每包恰一次流密码运算，混淆层不认证——认证由内层 QUIC 承担）；否决 01 草案的每包 AEAD（28B/包，认证放在混淆层无增量价值）。修正点：salt 取满 12B 作 ChaCha20 96-bit nonce（若仅 8B，birthday 界 2^32 包，万包/秒约 5 天即 keystream 复用＝双流密码本风险）；日派生＋±1 天时钟容忍（试昨/今/明三把）沿用 01 方案。

## 4. 实施计划（V3.1 / V3.2 / V3.3）

### V3.1 双模式传输（masquerade 收尾 ＋ obfs 基础设施）｜ 8–12 人日
- 目标：线缆形态二选一——默认"标准 h3 站点"，逃生舱"均匀随机字节"；全程可回滚、与 V2 节点共存。
- 改动模块：新增 `hydra-obfs`（XOR 变换/日派生密钥/每源令牌桶/缓冲池，约 600 行）；`hydra-client/src/transport.rs::create_shared_endpoint` 与 `hydra-node/src/server.rs::new` 接 `Endpoint::new_with_abstract_socket`；`NodeOptions` 增 mode/obfs 配置（配置系统未落地前用 env 过渡）；masquerade 收尾（h3 伪装响应、首包长度归一化）；分享链接 `?v=3&cap=wrap&mode=`＋证书指纹字段（顺带修 F14）。
- 验收（可测）：① masquerade 下裸 QUIC 探测/错钥握手 → h3 伪装响应或零字节静默，与真 h3 站对照无可区分差异；② obfs 下 Wireshark 读不出 Initial/ALPN/SNI，载荷过卡方随机性检验；③ obfs on 吞吐损失 <5%、off 零开销，64KB 大块往返回归；④ mode 未配置 = V2 行为，存量 V2 节点互通回归；⑤ 1 万垃圾 UDP 包零回应、内存/CPU 平稳。
- Phase B 合并：**吸收 P1-2 令牌桶限速**（在 obfs 层落地）；B5 配置系统若先行则直接接配置。

### V3.2 Hydra-Noise-PSK v2 握手｜ 8–10 人日（另需 Phase B 依赖升级 2–3 人日前置）
- 前置门：Phase B-6（rustls 0.23 ＋ ring 0.17 单版本收敛）完成。
- 目标：替换静态 HMAC token——前向安全、通道绑定、重放免疫、去 30s 时钟窗。
- 改动模块：引 snow（`Noise_NNpsk2_25519_ChaChaPoly_SHA256`，ring resolver）；`hydra-protocol` 增 msg1–msg3 消息流与 L0–L3 密钥层级、rekey 棘轮（2^24 帧/1GB/10min 任一先到）；双栈版本判别（0x00/0x03）＋ `auth_mode=auto|v3|v2`；服务端有界 LRU nonce 重放表；rustls exporter（export_keying_material）绑定进 k2/k3。
- 验收：① snow 标准测试向量通过；重放整段旧握手被拒、重放 msg1 被 nonce 表拦截；② 篡改任一字节 → 握手失败且静默关流（R2）；③ 跨 TLS 连接转发/重放握手字节无效（MITM 实验）；④ v2/v3 节点混编回归，版本字节判别无冲突；⑤ 系统时钟拨动 ±1h 握手仍成功；⑥ rekey 按阈值触发、旧密钥 zeroize。
- Phase B 合并：**吸收 P1-1 nonce 重放表**（v2 路径不再单独补，残余可重放风险如实记录、靠 v3 迁移收口）；P2-7 依赖升级以 Phase B 名义先行。

### V3.3 会话层多路径聚合｜ 15–25 人日（超 25 必须再拆，R5）
- 目标：兑现 RFC v1 核心卖点；聚合只给下载/大文件，视频永远直通（R4）。
- 改动模块：Splitter/Assembler 接入真实数据路径＋有界乱序窗口＋分片超时回收（修 P2 Assembler 遗留）；调度器（RFC §6 bandwidth/latency/loss 评分，参数用 Phase B 测速数据校准）；每路径独立 pacing＋50–200ms 随机相位去相关＋离散 padding（1K/4K/16K 档，03 §4）；已认证流的节点错误显式传播（reset(error_code)）。
- 验收：① 两好一差三节点聚合吞吐 ≥ 最优单节点 ×2；② 聚合中杀 1 节点：传输不中断、1GB 往返校验和零损坏（含 1%/5% 随机丢包注入）；③ 乱序窗口有界、分片超时回收有测试覆盖；④ 三路径抓包无同步突发（跨包时间戳相关性检验），padding 档位离散、与 obfs 长度不变性联合检验无新规律；⑤ 视频默认直通（集成测试断言）。
- Phase B/C 合并：**吸收 B1 测速重写**（校准数据源）、**B2 错误传播**、Phase C-1 聚合与 C-2 整形；Phase C 剩余（TLS 指纹 GREASE、BBR）不入 V3。

**合计 31–47 人日**（不含 Phase B 既有项）。Phase B 其余项（SSRF 过滤、日志脱敏、测试体系重建）与 V3 无耦合，维持原计划。每阶段结束跑一次三维度复审（审查总览执行原则 4）。

## 5. 密码套件定版

| 握手模式 | 曲线 | AEAD | KDF | domain separation 前缀 |
|---|---|---|---|---|
| `Noise_NNpsk2_25519_ChaChaPoly_SHA256`（snow＋ring resolver；线协议版本字节 0x03） | X25519（双方临时，ee → 前向安全） | ChaCha20-Poly1305（AES-256-GCM 可选，AES-NI 机器优先） | HKDF-SHA256：L0 PSK → L1 Noise 链 → L2（salt=TLS exporter）→ L3 rekey 棘轮 | `hydra v3 *`：handshake / data c2s / data s2c / rekey / cookie / tls-bind |

- AEAD nonce = `epoch(24b)‖dir(8b)‖seq(64b)`，每密钥单调递增绝不复用；BLAKE3 砍掉，node_id 用 SHA-256（02 §8-1 采纳）。
- 选 NNpsk2 而非 IKpsk2：IK 把静态公钥放明文＝可关联身份标识，违背防追踪目标（02 §2）。

## 6. 风险清单

1. **残余可探测性**：obfs 随机流在白名单/统计审查下仍是"不明加密 UDP"，可能被整段限速——逃生舱定位是"特征匹配下不可识别"，不是"统计下不可疑"（03 §2.2 如实定位，写入 README）；masquerade 残余：自签证书可被动区分于真站、对垃圾 UDP 零回应与真站行为有差（01 风险①）。缓解：能力边界如实标注；真证书问题上升老板（§7-2）。
2. **snow 依赖审计**：Cargo.lock 锁版本＋`cargo audit`/`cargo vet` 进 CI；ring 收敛单版本 0.17（02 禁止清单：双版本并存即打回）；snow 启用 ring resolver，禁默认 provider 混用。
3. **V3.3 数据损坏（最高工程风险）**：Assembler 现状无超时无窗口（P2 遗留），分片丢失＝GB 级静默损坏，直接违背"宁缺勿假"。**测试强制项（不通过不得发布）**：丢包注入 1%/5%、节点中途杀死、1GB 校验和比对、乱序交付 fuzz、未确认 chunk 超时重发路径全覆盖；达标前聚合仅对下载流量灰度，视频永走直通（R4）。
4. **quinn 0.11 跟改**：升级时 AsyncUdpSocket API 需跟改约半天（01 已核实）；非必要不升，与 rustls 升级解耦评估。

## 7. 给老板的开放问题（需拍板）

1. **obfs 密钥策略**：独立第二密码（分析师：防一处泄漏全暴露）vs 从 HYDRA_AUTH_KEY 派生（架构师草案：易用）。首席建议：独立密码，未配置则 obfs 不可启用。
2. **ACME 真证书是否入 V3 序列**：masquerade 做像上限取决于真证书（自签可被动区分）；代价是域名＋自动续期运维。不入则 masquerade 上限锁定。
3. **聚合拓扑确认**：跨节点带宽聚合只有多五元组一条路（单连接多 stream 聚合不了带宽），形态风险靠强制去相关整形兜底（03 §4）。确认"多节点聚合＋强制去相关"为 V3.3 形态？
4. **v2 删除窗口**：v3 观测 2 个发布周期后 auto → v3-only，整体删除 v2 路径（含 README/链接格式清理）。确认节奏。
5. **预算与压缩序**：合计 31–47 人日；若需压缩，首选缩减 V3.3（先两节点聚合、评分调度后置），V3.1/V3.2 不动。
