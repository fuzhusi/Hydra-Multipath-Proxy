## 一、总评分与结论

| 维度 | 评分（10 分制） | 一句话 |
|---|---|---|
| 安装/首次配置可走通性 | **3** | 非程序员在客户端侧能被 GUI 向导带通，但服务端部署要求 VPS + Rust 编译 + openssl，基本必卡 |
| 日常使用体验 | **6** | 添加节点/二维码分享/订阅/系统代理一键开关齐全，闭环完整 |
| 稳定性机制 | **7.5** | 断节点自愈、长下载防误杀、系统代理崩溃恢复都做了，且实现是认真的 |
| UI 吸引力 | **3** | 老板说"UI 很差"是准确的：默认 egui 皮肤 + emoji 当图标，与 Clash Verge 有明显代差 |
| 错误提示/自助排障 | **4.5** | 错误只进日志页文本框，且 GUI 测速根本测不出密钥/证书错误 |

**总分：4.8 / 10（按"给非程序员当日常工具"的标准）。**

**结论**：这个项目的"内功"（协议、安全、自愈、稳定性修复）明显高于"面子"（部署门槛、UI、错误引导）。它当前是一个**给作者自己和懂技术朋友用的工具**，不是给非程序员用的产品。要交付给广东移动的老板用，缺的不是功能，而是**预编译安装包、可视化部署、UI 重设计落地、把"静默失败"翻译成人话**这四件事。README 自己也很诚实（L7"个人自用工具"、L262"已知限制如实标注"），文档没有吹牛，这一点值得肯定。

## 二、亮点（有证据的）

1. **稳定性机制是真修了，不是写在文档里。** 长下载被掐问题（review/06 P2-1 指出的"每方向独立计时会误杀长下载"）已在 `hydra-node/src/tcp_server.rs:246-320` 修复：两个方向 pump 共享 `AtomicU64` 最后活跃时间戳（L250-255），只有连接整体空闲才关（L300），并有注释说明缘由（L247-249）。TUN 侧也有对应空闲回收（`hydra-client/src/tun.rs:85, 884`）。这对"挂机下载/看视频"的老板是**可感知的透明改善**。

2. **故障自愈对用户透明。** 传输失败自动标 Offline、切下一节点（最多 3 候选）、后台 30s 探测自动复活（README L25、L174）。用户感知就是"网闪了一下又好了"，不需要动手。

3. **系统代理一键 + 崩溃自动恢复。** GUI 启动代理就绪后自动设系统代理（main.rs:786-787），App 实现 `Drop`（main.rs:214）、托盘退出、崩溃恢复路径均有 `remove_system_proxy_static`（main.rs:909）。非程序员最怕"开了代理软件关掉后网页全打不开"，这里有兜底设计。

4. **分享/导入闭环完整。** 单节点"分享"弹窗出二维码（main.rs:1606-1736，240×240 图片 + 可复制链接），支持"从二维码图片导入/粘贴导入/文件导入"三路（main.rs:1209、1166、1246），完整链接含密钥+证书"导入即用"（main.rs:2438 有明确提示）。订阅支持多行/逐行 base64 自有格式，自动合并节点。

5. **排障表写得极好，是全仓库对"人"最友好的一段。** docs/guides/部署指南.md §4（L71-85）把"防火墙未放行 / 密钥不一致 / 端口错 / 证书不匹配"四种静默故障的症状、确认命令、修复逐一对照——因为设计上认证失败静默关流（反探测），副作用是三类故障"看起来一样"，作者没有回避这一点而是给了排查路径，态度诚实、内容可操作。

6. **诚实文化贯穿文档。** README L262"已知限制（如实标注）"逐条列出：单流、无 GeoIP、GUI 暂仅支持自签 pin 模式（L269）、ClientHello 指纹差异（L268）。UI 方案 v3 也直言"丑在默认 Visuals，不在能力"（UI重设计方案-v3.md L8）。docs/assessment/终端用户对比评估.md 甚至自评便捷性 3/10。

## 三、问题清单（按优先级）

### P0 —— 直接决定"老板能不能用起来"

**P0-1 没有预编译安装包，第一公里就走不通。**
部署指南 L12 白纸黑字："仓库内**没有远程发布产物**（无预编译包），必须在 VPS 本地构建（首次约 2-5 分钟）"。README 快速开始第一步就是 `cargo build --release`（L56）+ `openssl rand -hex 32`（L62）。非程序员不可能在 Windows 上装 Rust 工具链，更不可能在 VPS 上编译。
**建议**：CI（GitHub Actions）产出三平台 release 产物（含 wintun.dll 打包的 Windows zip/installer）；同时提供"一条 curl|bash"或 Docker 一键节点部署（Docker 路线已存在，部署指南 §2，但没有面向小白的组合脚本）。

**P0-2 服务端部署整体超出非程序员能力半径。**
即便给了二进制，"买 VPS → ssh 上去 → ufw 放行 443 → 把证书 .der 文件 scp 回 Windows → 再在 GUI 里填"是一整条命令行旅程。老板会死在 ssh 这一步。
**建议**：做一个"节点部署向导"（哪怕是最简 Web 表单脚本：输入 IP+密码，脚本代 ssh 完成全部步骤并把凭据打包成 `hydra://` 完整链接发回来——完整链接导入即用的能力其实已经有了，缺的只是把部署也串起来）。

**P0-3 GUI 测速是"假安心"：只测 TCP connect，测不出密钥/证书错误。**
`main.rs:411-422` 的节点测试只是 `TcpStream::connect`（3s 超时）。也就是说：密钥不一致、证书文件选错、握手失败——**测试全部显示通过**，直到真正上网时才发现不通。而部署指南 §4 明确说密钥不一致是"两端日志看起来一样：什么都没有"的最隐蔽故障。老板遇到时的体验是"显示绿了但就是上不了网"，且无任何提示指向根因。
**建议**：节点测试升级为完整链路探测（TCP+TLS+Noise 握手到目标连接一步，对节点固定探测地址，如 `connect:80`），握手成功才算绿；握手失败时区分"TCP 不通 / TLS 证书不匹配 / 认证失败"三种文案。这是把部署指南 §4 的排障表**内建到 GUI**，价值极高。

**P0-4 UI 现状与老板期望的代差是真实的。**
现状：默认 egui 皮肤、侧栏是 `SelectableLabel` 文字列表加 emoji 前缀（main.rs:1757-1776，"🌐 节点"“📡 订阅”）、状态卡是 `Frame::group`（main.rs:2042）——灰底方块、无圆角、无图标字体、无速率曲线图、无主题切换。对比 Clash Verge Rev 的"侧栏图标 + 卡片网格 + 实时速率曲线 + 延迟色点"，差距不是打磨级而是代差级。UI重设计方案-v3.md（L8）自己也承认"默认皮肤丑"。README L282 明确 UI 重设计**尚未实施**（P0-P2 约 10 人日，方案已定稿）。
**诚实评分：3/10**。打 3 不打 2，是因为布局结构（左侧导航六区+卡片）是对的、信息不乱，缺的是皮肤与图表。
**建议**：按已定稿的 v3 方案直接施工，优先 P0（模块化拆分+自定义暗色 Visuals+侧栏图标）与 P1（仪表盘速率图 + 延迟色点徽章）。10 人日的投入是这个项目**性价比最高的一笔 UI 开销**，方案都写好了，只欠执行。

### P1 —— 影响日常体验与自助能力

**P1-1 错误提示全部沉到"日志"页文本框，无弹窗、无"下一步该干什么"。**
启动失败、配置保存失败、导入失败一律 `add_log(...)`（如 main.rs:641、397）。日志页只是带时间戳的字符串列表（main.rs:602-612，上限 100 条）。老板不看日志，也不会把 `地址解析错误: invalid socket address syntax` 翻译成"端口要填 1-65535 的数字"。
**建议**：致命错误用模态对话框 + 人话文案 + 建议动作（"密钥应为 64 位 hex 字符，去节点 VPS 上运行 xxx 获取"）；日志页加级别过滤与颜色（方案 v3 已含）。

**P1-2 首启向导是静态文字清单，不是可交互向导。**
`wizard_lines()`（main.rs:357-374）只是四行说明文字让用户自己切页去操作，步骤间无引导跳转、无完成校验。对非程序员，"向导"应该是：填密钥→验格式→选证书→验指纹→填节点→点测试→启动，一步一步带。
**建议**：做成遮罩式分步对话框（v3 方案 L145 已规划"向导保留为全屏遮罩模式"），每步带校验与"上一步/下一步"。

**P1-3 TUN 模式完全在 CLI 世界里，GUI 用户够不着。**
README L117-145：TUN 需要 wintun.dll、管理员运行、一堆 `HYDRA_TUN_*` 环境变量；且 v1 边界一堆（仅 TCP、无 DNS 劫持、仅拦 4 个端口）。这是"免配置全局代理"的最大卖点，但目标用户（非程序员）恰恰是唯一用不了它的人群。另外"强杀后路由恢复"依赖下次启动幂等清理（README L128-129），人工验证清单（L142-145）也承认真实设备路径需手动确认。
**建议**：GUI 设置页加"TUN 模式"开关（自动请求管理员权限、自动带 wintun.dll、掉线路由自动清理）；在没做好之前，GUI 里应明示"TUN 请用命令行"，避免用户去翻环境变量。

**P1-4 GUI 不支持真证书（ACME）模式。**
README L269："GUI 暂仅支持自签 pin 模式（真证书部署走 CLI）"。对用户这造成割裂：文档推荐长期用真证书（L77"推荐长期使用"），但图形界面用不了。
**建议**：GUI 节点编辑框加"信任模式"单选（pin/ca）+ SNI 输入框即可，改动量小（config 已有字段语义），性价比高。

**P1-5 广东移动网络现实：分流默认关闭 + 无 GeoIP。**
国内直连分流默认关（README L42"隐私优先"），且是纯域名后缀表无 GeoIP（L265）。对老板的实际体验：默认配置下访问国内网站也绕广东→VPS→绕回来，**速度反而变慢**（终端用户对比评估 §3 也承认"不分流全绕 VPS"）。隐私优先是设计立场，但对"广东移动看 B 站"场景，默认关闭就是默认难用。
**建议**：首启向导里给一个二选一（"国内网站直连（推荐）/ 全部走代理"），把开关显性化；中期把 CN 表升级为域名+IP 段双判定。

**P1-6 订阅是自有格式，生态为零。**
README L265："订阅为自有格式（不对接机场）"。老板哪天拿到一个机场订阅链接（base64 的 vmess/ss 列表），导入会失败且不知道为什么。
**建议**：短期在订阅导入失败的报错里明说"仅支持 Hydra 格式链接"；中期可只读解析常见格式（vmess/ss/trojan URL）做展示，能转则转、不能转给明确文案。

### P2 —— 打磨项

- **P2-1 main.rs 单文件 3236 行**（v3 方案 L3、L84 均自证），六页 UI + 托盘 + 通道轮询全在一个文件。功能还在正确迭代，但继续堆会拖慢修复速度。→ 按 v3 方案 P0 拆分即可，与 UI 重设计同批做。
- **P2-2 启动预热"数十秒"无进度反馈。** 启动提示只有一句"节点预热可能需要数十秒"（main.rs:768），就绪靠 60s watcher 轮询 bound_addr（main.rs:720-732）。老板在这几十秒里只会觉得"点了没反应"。→ 加进度指示/骨架屏，至少转圈。
- **P2-3 启动即自动设系统代理**（main.rs:786-787）无确认。对老板可能算贴心，但一旦与本机其他代理软件共存会互相顶掉（TUN 文档 L138 也警告环路风险）。→ 设置页加"启动后自动设置系统代理"开关（默认开）。
- **P2-4 节点测速指标单薄**：仅 TCP connect RTT，无真实下载测速；多节点评分调度的"被动吞吐差分"（README L27）存在但 UI 上看不到各节点实际速度。→ 行内加"测速（下载 1MB）"按钮。
- **P2-5 无开机自启/静默启动。** 竞品（Verge）标配，托盘已有，缺一个注册表 Run 项 + 选项开关。

## 四、按老板旅程的逐步走查小结

1. **安装/编译/首次配置**：❌ 卡死在第一步（无预编译包，P0-1/P0-2）。假设有人代装好节点+客户端，GUI 首启向导文字（main.rs:357）能指路，"全局凭据折叠区 → 填密钥 → 浏览证书 → 添加节点 → 启动"流程本身通顺，配置持久化 + 双击即用（main.rs:370-372）体验良好。**综合：有人带则能走通，无人带则走不通。**
2. **日常使用**：✅ 闭环完整——添加/编辑/删除节点、二维码分享、图片导入、订阅、系统代理开关、托盘、关窗到托盘都有（README L39、main.rs 各处）。短板是无弹窗反馈（P1-1）和启动慢无进度（P2-2）。
3. **稳定性**：✅ 最好的一部分。断节点自动切换+自动复活（README L25）；长下载防误杀已实修（tcp_server.rs:246-320，这是 review/06 P2-1 的正确修复）；系统代理崩溃恢复有 Drop 兜底（main.rs:214）。TUN 是实验品且 GUI 够不着（P1-3）。
4. **UI 吸引力**：❌ 老板判断正确，3/10（P0-4）。布局骨架对，皮肤是原始 egui；好消息是修复方案已定稿只差 10 人日施工。
5. **错误提示**：❌ 4.5/10。错误进日志框（P1-1），最致命的是测速假绿测不出密钥/证书问题（P0-3），静默关流设计让"连不上"毫无线索——排障表（部署指南 §4）很好但那是写给运维看的，老板需要的是 GUI 里的人话。

## 五、改进路线建议（按投入产出排序）

| 优先级 | 事项 | 对应问题 | 预估 | 对老板的可感知收益 |
|---|---|---|---|---|
| 1 | CI 产出 Windows 预编译包（含 wintun.dll）+ 节点一键部署脚本 | P0-1/P0-2 | 2-3 天 | 从"装不了"到"下载双击" |
| 2 | UI 重设计 v3 方案 P0+P1 落地（暗色主题/图标/速率图/延迟色点） | P0-4 | 7 人日（方案已定稿） | 从"很丑"到"像个正经软件" |
| 3 | 节点测试升级为完整握手探测 + 分型错误文案 | P0-3 | 2 天 | "显示绿就能用，红就告诉你为什么" |
| 4 | 致命错误改模态对话框 + 人话 + 建议动作 | P1-1 | 1-2 天 | 出错能自助 |
| 5 | 交互式首启向导（分步+校验+分流二选一） | P1-2/P1-5 | 2-3 天 | 首启成功率大增，国内速度不再垫底 |
| 6 | GUI 支持 ca 信任模式 + TUN 开关（带管理员提权） | P1-3/P1-4 | 3-5 天 | 功能不割裂 |
| 7 | 开机自启 + 启动进度指示 + 节点下载测速 | P2 系列 | 2-3 天 | 日常顺手度 |

**一句话给决策者**：这个项目的地基（协议/安全/稳定性）是认真的、修 bug 是动真格的，但"交付给非程序员"还差最后一层壳——先做第 1、2、3 项（约两周工作量），老板就能真的自己用起来；在此之前，它只能由懂技术的人代装代维护。
