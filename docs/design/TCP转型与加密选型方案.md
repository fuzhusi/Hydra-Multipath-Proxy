# 转型方案：全面 TCP 化 + 开源加密方案选型

- 日期：2026-10-04 ｜ 状态：**待老板批准后执行**
- 决策背景：老板网络（广东移动→境外 VPS）存在**UDP 回程 QoS 丢包**（tcpdump 实证：上行通/回程丢），QUIC/UDP 路线在该网络环境下不可用。老板拍板：放弃 UDP，全面转 TCP；加密方式从开源项目找成熟方案。

---

## 1. 开源加密/传输方案选型研究

| 方案 | 原理 | 优点 | 缺点 | 与本项目契合度 |
|---|---|---|---|---|
| **Trojan 协议** | 标准 TLS（443）内：`SHA224(password) 认证头 + CRLF + 目标地址帧 + 双向流` | **极简**（百行级）；经大规模实战检验；流量形态=标准 HTTPS 访问；生态成熟（参考实现多） | 无前向安全增强（TLS 本身有）；主动探测下无网站伪装 | ★★★★★ **推荐**：与我们现有架构几乎同构（TLS+pinning+token+地址帧），改动最小 |
| Shadowsocks-2022 | BLAKE3/AES-GCM AEAD 分帧，抗重放+抗长度指纹 | 密码学设计最规范（LDAT 抗探测） | 无站点伪装；完整实现复杂度高；我们已有等价物（noise/帧协议） | ★★ |
| Xray REALITY | 借用真实网站证书，主动探测转发到真站 | 抗主动探测最强 | 仅 Xray 生态；自实现=数月级 | ★（远期评估） |
| VLESS | 轻量无加密（依赖外层 TLS） | 简单 | 自身无加密，需配 TLS | ★★（Trojan 已覆盖） |

**选型结论（v2 修订，老板两次质询后定版）：TLS 1.3（ACME 真证书）+ 复用 V3.2 Noise-PSK 应用层握手 + 私有帧协议。**
理由：①TLS 管机密性/前向安全/伪装（真证书=标准 HTTPS 形态），Noise-PSK 管双向认证+抗重放+无时钟窗（**比 Trojan 单向 SHA224 哈希头强一个档次**）；②handshake.rs 为通用 AsyncRead/Write 实现，**直接平移到 TCP 流，代码复用最大化**（V3.2 资产救活）；③线缆格式私有（现有 DPI 规则零命中）；④与 Xray 的差异化 = 多节点调度体系（见 §6）。
**借鉴边界**：成熟做法照收（TLS、ACME、反探测回退页、Range 下载调度思想）；线缆格式保持私有。

## §6 修订：多节点聚合在 TCP 下的重新定位（老板质询后）

| 形态 | 状态 | 结论 |
|---|---|---|
| 字节级通道聚合（V3.4） | **正式放弃** | TCP 自带可靠有序，跨节点拆字节的复杂度换不来对等收益 |
| 连接级加权分发 | ✅ 已实现 | 多节点分担连接、故障自愈 |
| **多节点并行下载**（新差异化方向 ⭐） | 规划 | 大文件按 HTTP Range 切块、多节点并行拉取拼装（对标 ADM/IDM 多线程下载）——**单节点带宽受限时 N 节点=N 倍速，Xray/Trojan/REALITY 均无此能力**，TCP 下天然合理 |

## 2. 目标架构

```
浏览器 → 本地 SOCKS5/HTTP(127.0.0.1:1080) → [TLS over TCP 443] → 节点 → 目标网站
                                              ↑ Trojan 式协议：
                                                SHA224(auth_key) 认证头 56B
                                                + CRLF + [addr_len u16 BE][addr]
                                                + CRLF → 节点校验 → 目标 TCP → 双向流
```

- **节点同时监听 TCP 443**（QUIC/UDP 监听默认关闭，保留一个版本周期后移除）
- **保留**：证书 pinning（自签）+ 兼容 ACME 真证书、SSRF 过滤、SSRF/资源上限、健康检查、GUI 全部功能
- **废弃**：QUIC 连接池、channel 聚合（V3.4）、ACK/NACK、obfs UDP 混淆、双栈认证的 UDP 路径——代码保留一个版本周期（`legacy` 标注）后删除

## 3. 分阶段工作分解（子 agent 任务包）

### Wave 1：新 TCP 协议核心（P0）
- `hydra-protocol/src/trojan_frame.rs`（新）：认证头生成/校验（SHA224 hex，常量时间比较）、地址帧编解码
- `hydra-node/src/tcp_server.rs`：重写 TCP 监听（替换现 tcp.rs，根治挂起/e2e 缺陷——新实现不复用旧 tcp_transport 的流关闭语义）
- `hydra-client/src/tcp_transport.rs`：重写客户端侧
- 文件所有权：上述 + 相关测试；禁触 GUI/QUIC 路径
- **验收门**：①64KB/1MB/10MB 三档 E2E 校验和逐字节相等 ②错误认证头静默关流 ③半关闭语义正确 ④全量回归绿

### Wave 2：全面切换 + UDP 降级（P0）
- 客户端/节点默认传输=tcp；`HYDRA_TRANSPORT=quic` 可回退（标注 legacy）；GUI 设置页加传输选择
- 分享链接 v2 增加 `tp=tcp` 默认值；README 协议章节重写
- **验收门**：真实服务器（43.133.91.218）实测连通 + 浏览器网页 + 视频流 10 分钟 + 全量回归绿

### Wave 3：清理与加固（P1）
- 删除 QUIC/UDP 死路径（保留 git 历史）；删除 obfs UDP 混淆模块
- 证书双支持：自签 pinning（现状）+ ACME 真证书可选（`HYDRA_ACME_DOMAIN`）
- 可选探测伪装增强：非认证 IP 访问 443/TCP 时反代到一个静态页面（Trojan 经典手法，抗主动探测）

## 5. 风险

- Trojan 认证头为明文哈希（TLS 内），无 PSK 前向安全增强——TLS 1.3 已提供前向安全，可接受（如实标注）
- 广东移动对境外 TCP 443 也可能限速——若出现，后续评估端口/真证书优化（数据说话）
